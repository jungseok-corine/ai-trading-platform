# INFERRED-INTENT.md — 코드로 역추론한 제작자의 목표

> 마지막 갱신: 2026-06-23  
> 이 문서는 실제 발언이나 요구사항 문서가 아닌, 코드·주석·커밋 히스토리에서  
> 역추론한 제작 의도다. 틀릴 수 있으며, 수정을 환영한다.

---

## 1. 핵심 철학: "자동화하되, 실행권은 사람에게"

코드 전반에서 가장 반복적으로 나타나는 패턴은 **인간 승인 게이트**다.

```python
# analysis_proposal_service.py
version = StrategyVersion(
    ...
    status=StrategyVersionStatus.DRAFT,         # 항상 DRAFT
    parameters={**proposed_params,
                "auto_trade_enabled": False},    # 항상 꺼짐
)
```

AI는 항상 `pending` 제안을 생성하고, 승인하더라도 `DRAFT + auto_trade_enabled=False`가 강제된다.  
이 코드는 "AI가 실수하더라도 사람이 최종 확인하기 전까지는 아무 일도 일어나지 않는다"는  
설계 의도를 명시적으로 구현한 것이다.

**추론**: 제작자는 AI에게 분석과 제안은 맡기되, 실행 권한은 절대 주고 싶지 않다.  
시스템이 더 똑똑해지더라도 이 원칙이 유지되길 원한다.

---

## 2. "실험 시스템"을 먼저, 자동매매는 나중

연구 루프(스캐너 → 후보 → 배정 → 실험 → 제안 → 승인 → 회고)는 자동매매보다  
훨씬 정교하게 구현되어 있다. 반면 실제 자동매매는 "MA 크로스" 하나가 대부분이다.

**추론**: 초기 목표는 "어느 전략이 효과적인가"를 체계적으로 실험하는 것이었다.  
자동매매는 실험 결과를 검증하는 수단이지, 그 자체가 목적이 아니다.  
제작자는 "잘 모르면서 실제 돈을 쓰는" 것을 피하려 했다.

---

## 3. 안전장치는 과잉일 정도로 중복

```
계층 1: config.kis_real_trading_enabled = False (기본값)
계층 2: KisRealBroker.place_order() → RealTradingDisabledError
계층 3: auto_trade_enabled = False (버전 기본값)
계층 4: 유니버스: PAPER 계좌 확인 + universe_auto_trade 옵트인
계층 5: RiskService: 6가지 룰 동시 검사
계층 6: LiveAccountRegistration: emergency_stop=True 강제
```

하나의 버그나 실수가 실거래로 이어지지 않도록 방어선을 6겹 쳤다.  
**추론**: 제작자는 "한 번의 실수로 실제 돈을 잃는 상황"을 극도로 두려워한다.  
이 코드를 쓸 때 실제 계좌를 연결하려는 의도가 있었거나, 연결할 계획이 있었다.

---

## 4. 미국 시장은 "1등 시민"으로 취급하지 않음

- EDGAR 수집기, US 브로커 라우팅, US 공시 분석은 구현되어 있다.
- 그러나 US 전략은 `market=US` 파라미터로만 구분되고, 전용 UI 섹션이 없다.
- 미장 데이터 갱신 스케줄러(`us_market_refresh`)는 기본 비활성이다.

**추론**: 미국 시장 지원은 "있으면 좋은 것"이지 핵심 목표가 아니었다.  
주요 개발 동기는 한국 시장(KIS OpenAPI)이며, 미국은 점진적으로 확장하는 방향이다.

---

## 5. 오퍼레이션 가시성을 중요하게 생각함

- "운영 종합", "운영 추세", "분석 감사", "AI 비용", "데이터 신선도" 섹션이 별도로 있다.
- `operations_digest_scheduler`가 있어 매일 요약 리포트를 생성한다.
- 모든 거래·신호·제안이 DB에 기록되고 조회 가능하다.

**추론**: 제작자는 "시스템이 지금 뭘 하고 있는지 언제든 확인할 수 있어야 한다"는  
원칙을 갖고 있다. 블랙박스 자동화를 싫어하며, 모든 결정의 이유가 추적 가능해야 한다.

---

## 6. AI는 "조언자"로 고정하고 싶다

CLAUDE.md에 명시된 원칙이 코드에도 구현되어 있다:
- AI 제안은 항상 `pending` 상태로 저장 (자동 실행 없음)
- AI가 생성한 버전은 항상 `DRAFT` (자동 활성화 없음)
- AI 비용 추적 섹션이 별도로 존재 (비용 인식)

**추론**: 제작자는 AI를 완전히 신뢰하지 않으며, AI의 역할을 "데이터 정리 + 제안 초안 작성"으로  
의도적으로 제한하고 싶다. AI가 점점 똑똑해지더라도 이 경계가 유지되길 바란다.

---

## 7. 이 시스템의 궁극적 목표 (추론)

코드 전체를 종합하면, 제작자가 원하는 것은 아마도 이것이다:

> **"시장을 자동으로 감시하고, 유망한 전략을 자동으로 발굴·실험하며,  
> AI가 개선 방향을 제안하면 내가 검토 후 승인하는 시스템.  
> 최종적으로 검증된 전략만 모의투자로 운용하고,  
> 실거래는 내가 확신할 때만, 내가 직접 켠다."**

이것은 자동매매 봇이 아니라 **의사결정 보조 시스템**이다.  
사람의 시간을 아끼되, 판단은 사람이 한다.
