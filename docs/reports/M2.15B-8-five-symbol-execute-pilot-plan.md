## 5. Future execute command plan (초안 — 실행 금지)

### CLI 능력 점검 결과

`scripts/collect_daily_candles.py` 지원: `--symbols`(콤마 다종목) · `--count` · `--execute` ·
`--confirm-daily-candle-collection` · `--coverage-only` · `--overwrite` · `--json`.
**미지원: `--sleep`/간격 · `--end-date` · 오케스트레이션 레벨 stop-on-error.**
- collector.collect()는 **종목을 for 루프로 순차 처리**(구조적으로 concurrency=1).
- 단, `_collect_one`은 **provider 예외를 종목 단위로 흡수**(failed_transient/permanent로 기록 후 다음 종목
  진행) → 다종목 단일 명령은 "stop-on-unexpected-error"를 **보장하지 않는다**.
- 종목 간 sleep 옵션 없음(요청 간 간격은 provider의 `rate_limit_min_interval_seconds`만 적용).

### 권장(A): 종목별 순차 수동 실행 — **1차 pilot 권장**

각 종목을 개별 명령으로 실행하고 **매 종목 후 DB 검증 + 실패 시 즉시 중단**. operator가 stop 통제권 보유.

```bash
# 1) (선) dry-run/coverage 프리체크 — 5종목
python scripts/collect_daily_candles.py --symbols 005930,000660,035420,005380,051910 --count 252
python scripts/collect_daily_candles.py --symbols 005930,000660,035420,005380,051910 --coverage-only

# 2) 신규 4종을 한 종목씩 순차 execute (005930은 control: 이미 252, 재실행 시 conflict 예상 → pilot 대상서 제외 가능)
for S in 000660 035420 005380 051910; do
  python scripts/collect_daily_candles.py --symbols "$S" --count 252 \
    --execute --confirm-daily-candle-collection --json
  # 각 종목 후: 1d 카운트/중복/null 검증 → 이상 시 STOP (다음 종목 실행 금지)
  sleep 5   # EGW00201 여유(종목 간 간격)
done
```

- 005930은 control(이미 252). 재수집하면 §7의 당일봉 conflict가 날 수 있어 **신규 4종만** execute하는 것을
  권장(005930은 검증·비교 기준으로만 유지). 5종 모두 적재를 원하면 005930도 포함하되 `conflict(1)` 예상.

### 대안(B): 다종목 단일 명령

```bash
python scripts/collect_daily_candles.py --symbols 000660,035420,005380,051910 --count 252 \
  --execute --confirm-daily-candle-collection --json
```

- 장점: 한 번에. 단점: per-symbol 실패를 흡수하고 계속 진행(즉시 stop 불가), 1회 commit. **1차 pilot에는 (A)
  권장**, (B)는 CLI에 stop-on-error/sleep이 추가된 뒤(M2.15B-8a) 사용 권장.

공통: count=252 · adjusted 기본 False(원주가, CLI 미노출이라 기본값 유지) · overwrite **미지정**(=False).

## 6. Concurrency / rate-limit (EGW00201) policy

- EGW00201("초당 거래건수 초과")은 이전 라이브 프로브/pilot에서 1회씩 관측 → provider 내장 backoff/retry로 복구.
- 5종목 pilot은 **concurrency=1**(순차) 고정 — collector 구조상 동시 호출 없음. **동시성 증가 금지 · API 연타 금지.**
- 종목 간 **sleep 5s**(권장 A의 수동 루프)로 추가 여유. CLI 자체 sleep 미지원이라 shell 레벨로 확보.
- **반복 EGW00201이 backoff로도 복구되지 않아 완료 불가하면 즉시 중단·보고**(부분 상태 기록).

## 7. Current-day candle policy

- **확정 과거봉 = 불변(immutable)** 으로 취급.
- **당일 거래일봉은 장중 drift** 가능(예: M2.15B-7에서 005930 20260629 close 323000→324000, vol 51.9M→53.4M).
- **overwrite=False를 기본 유지** → 기존 행과 다른 당일봉은 `conflict`로 보고되고 **덮어쓰지 않음**(정상·안전).
- 신규 4종은 일봉 0이라 첫 적재 시 conflict 없이 252봉 insert 예상. 당일봉 포함 여부는 provider 응답에 따름.
- **당일봉 refresh/overwrite 정책은 별도 미래 결정** — 본 pilot로 해결하지 않으며 overwrite 동작을 구현하지 않는다.

## 10. Failure / stop conditions

아래 중 하나라도 발생 시 **즉시 중단 · 남은 종목 실행 금지 · 부분 상태 보고 · 복구 작업 권고**:

- 신규 종목에 대해 provider가 부분 데이터 반환(예 252 크게 미달, 원인 불명).
- 반복 EGW00201이 backoff로도 복구되지 않음.
- DB 행 수가 예상과 다르게 변함.
- 중복 행 발생 / OHLCV null 발생.
- 비선정 종목에 `1d` 행이 생김.
- 본 작업으로 SignalLog/Trade/Order 변동.
- 스케줄러/디스패처 변동.
- 마이그레이션 출현 / 런타임 코드 변경 필요.

→ 부분 적재가 발생하면 **이미 적재된 종목은 멱등이라 보존**, 실패 종목만 재시도(별도 판단). 강제 정리/삭제 금지.
