# M2.15B-3 — Daily Candle Live Read-Only Probe (no DB writes)

> 라이브 read-only 프로브 + 문서. **DB 쓰기 0 · execute-pilot 미실행 · 일봉 row 미삽입 · SignalLog/Trade/Order
> 미생성 · KIS 주문 API 미호출 · 마이그레이션 없음 · 스케줄러/디스패처 없음 · M2.14B-3d 미승인.**
> 목적: M2.15B-2의 `get_daily_candles`가 실제 KIS read-only로 일봉 OHLCV를 가져올 수 있는지 1종목만 검증.

## 1. Executive summary

**성공.** KIS read-only 일봉 엔드포인트가 동작하고, `get_daily_candles`가 OHLCV/거래량/거래대금을 정확히
매핑한다. 단 **1회 호출은 ~100봉(KIS 페이지 한도)** 만 반환 → **252봉엔 페이지네이션 필요**(M2.15B-1에서 예상한
갭 확인). DB 쓰기 0, 안전 불변식 유지. 다음은 페이지네이션 추가 후 execute-pilot(별도 승인).

## 7. 252-candle feasibility

- **1회 호출 ≈ 100봉(KIS 페이지 한도)** 확인 → 252봉은 **페이지네이션 필요**: 날짜 윈도우를 3구간(예
  최근→-100→-200→-252)으로 나눠 3회 호출 + 중복 거래일 dedupe.
- 즉 **252봉 수집은 기술적으로 가능**하나, `get_daily_candles`(또는 collector)에 **다중 호출/날짜 분할 로직
  추가가 선행**돼야 한다(M2.15B-4).

---

## 8. Rate-limit observation

이번 프로브(2회 read-only 호출)에서 rate-limit 미관측. 단 252봉×다종목 수집 시 호출량이 늘어나므로 기존
`_request`의 backoff/cooldown(EGW00201) + collector의 동시성 1·간격 정책을 유지해야 한다(M2.14O/M2.15B-1).

## 10. Recommendation

- **프로브 성공** → 다음: **M2.15B-4(별도 승인) — `get_daily_candles` 페이지네이션 추가**(1회 100봉 한도 →
  252봉 다중 호출/dedupe) + 테스트(MockTransport). 그 뒤 **execute-pilot 1~5종목**(라이브 read-only 수집 →
  market_data `1d` 적재)도 별도 승인 시.
- 수정주가(`FID_ORG_ADJ_PRC=1`) 채택 여부, trading_value 컬럼 추가 여부는 M2.15B-4 설계에서 결정(컬럼은 별도
  승인 마이그레이션).
- **execute-pilot은 여전히 미승인** — 본 프로브는 read-only 검증만.
