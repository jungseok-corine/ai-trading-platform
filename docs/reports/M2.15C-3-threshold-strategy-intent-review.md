# M2.15C-3 — Leader Trend Threshold / Strategy-Intent Review (docs-only decision)

> **문서/의사결정만.** 런타임 코드/임계값 미변경 · 테스트 미변경 · 후보 영속화 없음 · 라이브 KIS 0 · DB write 0 ·
> 마이그레이션 없음 · SignalLog/Trade/Order 0 · 스케줄러/디스패처 0 · M2.14B-3d 미승인. **후보는 매수 신호가 아니다.**
> 본 작업은 스캐너가 대형 52주 gain/range 경고를 어떻게 다뤄야 하는지에 대한 **정책 권고 + M2.15C-4 구현 계획**만
> 산출한다. 권고를 구현하지 않는다.

---

## 1. Executive summary

현 스캐너는 `range_ratio>4` 또는 `gain>500%`를 **하드 블록**(operationally_safe=False)으로 처리해, **Candidate B가
의도적으로 노리는 강한 주도주(005930·000660)** 를 "데이터 의심"으로 묶고 있다. M2.15C-2에서 **adjusted=True가
high/low를 raw와 동일하게 반환**(수정주가 아티팩트 아님)했고, 본 리뷰의 read-only 분석에서 **최대 일일 종가 점프가
5종 모두 ≤19.1%**(분할 같은 불연속 없음), 저가 구간은 **다일 연속**(005930 21일·000660 33일 near-low)임을 확인했다.
즉 데이터는 **무결**하며 대형 gain은 **실제 1년 추세**다. → **권고: Option B** — 데이터 무결성 오류와 전략-극단
경고를 분리하고, **gain/range는 (데이터가 깨끗할 때) 비차단 `strategy_extreme` 경고로 강등**. 구현은 **Option C의
필드 분리 모델**로 M2.15C-4에서. **본 작업은 임계값/코드를 바꾸지 않는다.**

## 2. Current scanner behavior (M2.15C-1, 변경 없음)

`leader_trend_scanner.compute_metrics`:
- **하드 invalid**(→`invalid_data`, safe=False): `<252`(insufficient), nonpositive O/H/L/C, `high<low`,
  close∉[low,high], null/파싱불가, 중복 거래일.
- **원주가/스케일 경고**(→ safe=False, 후보면 `*_raw_needs_adjusted_review`): `range_ratio>4`, `gain>500%`,
  일일 종가 점프 `>50%`.
- 경고 1개라도 있으면 `operationally_safe_for_classification=False`.

문제: 위 3개 "경고"는 **성격이 다른 것을 한 통에 묶는다** — `range_ratio>4`·`gain>500%`는 **전략-극단**(강한 추세)
신호일 수 있고, 일일점프`>50%`만이 진짜 분할/조정 의심에 가깝다.

## 3. Strategy intent (M2.15A 설계)

- **Candidate A**: `gain<=200` AND `dd<=10` — 52주 고점 근처의 **상대적 초기 단계 주도주**.
- **Candidate B**: `gain>=200` AND `dd<=20` — **이미 저점 대비 크게 오른 강한 주도주**이나 고점에 충분히 근접.
- A/B는 **필터이지 매수 신호가 아니다.** **Candidate B는 논리적으로 매우 큰 gain을 허용**한다 → **큰 gain 자체를
  invalid로 취급하면 전략 의도와 충돌**. 데이터 무결성 이슈와 전략-리스크 이슈는 **분리**돼야 한다.

## 4. What M2.15C-2 proved

- adjusted=True의 **high_52w·low_52w가 raw와 정확히 일치**(5종 전부) → 대형 range는 **수정주가 미반영 아티팩트가
  아님**.
- close/gain/dd 미세차는 진행 중 당일봉 라이브 갱신 탓.
- 운영 후보: raw 0 · adjusted 0(동일). → **수정주가로 경고가 풀리지 않음**(Option "adjusted 채택" 기각, M2.15C-2).

## 7. Policy options

**Option A — 현 하드 블록 유지**: range>4·gain>500% 계속 차단. 장점: 매우 보수적, 분할/기형 데이터 방어. 단점:
진짜 극단 주도주 차단(Candidate B 의도와 충돌), M2.15C-2가 adjusted로도 안 풀림을 증명 → 차단 명분 약함.

**Option B — 데이터 무결성 ↔ 전략-극단 분리(권고)**: 하드 invalid는 유지(insufficient/nonpositive/high<low/
close 범위밖/중복일/null/**분할 같은 미설명 일일점프**/조정-원주가 불일치). range>4·gain>500%는 **데이터가
깨끗하면**(분할 점프 없음·저가 다일 연속·OHLCV 완전·adjusted≈raw) **비차단 `strategy_extreme` 경고**로 강등 →
Candidate B가 **운영 분류 가능**하되 리스크 경고 표시. 장점: 전략 의도 부합, 강한 주도주 보존. 단점: 변동성 큰
종목 통과 → 다운스트림 리스크 통제 필요.

**Option C — 2계층 출력**: `operationally_safe`는 엄격 유지하되 `candidate_bucket_research`(차단돼도 A/B 표시) +
상태 필드(`data_integrity_status`/`adjustment_status`/`strategy_extreme_status`/`candidate_bucket_research`/
`candidate_bucket_operational`) 추가. 장점: 최대 명료성, 한 버킷에 의미 뭉개지 않음. 단점: 코드/API/UI 복잡도↑.

**Option D — 프로파일 파라미터화**(conservative/research/leader_aggressive): 유연하나 종목·백테스트 적은 현
시점엔 시기상조.

## 8. Recommended policy → **Option B (구현은 Option C의 필드 분리로)**

- **gain/range 자체를 하드 블록으로 쓰지 않는다.** 하드 invalid 체크는 **그대로 엄격 유지.**
- 대형 range/gain은 **`strategy_extreme_warning`**(데이터 무결성과 분리)로 취급.
- **실제 데이터 무결성 증거가 있을 때만 하드 차단**: 불가능한 OHLC · 중복일 · 결측 OHLC · nonpositive · 고립 이상
  봉 · **미설명 분할 같은 일일점프(>50%)** · 조정/원주가 불일치(M2.15C-2식 비교).
- Candidate B는 **데이터가 깨끗하면 후보로 노출**하되 **high-extension/high-risk로 명확히 표기.**
- 구현은 **Option C의 명시 상태 필드**(아래 §10)로 하여 research vs operational을 분리 — B의 의미를 C의 구조로 표현.
- (참고) `adjustment_status`는 M2.15C-2 결과 반영: 본 5종은 adjusted≈raw → "no_artifact". 진짜 불일치 종목에서만
  `needs_adjusted_review`.

## 9. Rejected alternatives

- **Option A 기각**: 데이터 무결(일일점프≤19.1%, 저가 다일 연속, adjusted=raw)인데도 강한 주도주를 차단 →
  전략 무력화. M2.15C-2가 adjusted 명분도 제거.
- **Option D 보류**: 프로파일 분기는 종목 수·백테스트가 쌓인 뒤(예 20종+/실측 대조) 재검토.

## 10. Proposed M2.15C-4 implementation plan (별도 승인)

**범위(읽기 전용 유지)**: 스캐너 경고 모델 리팩터 — 단일 `data_quality_warnings`를 **계층화**:
- `hard_errors`(invalid_data 유발) · `adjustment_warnings`(원주가/조정 불일치 시) · `strategy_extreme_warnings`(range/gain).
- 분리 상태 필드: `is_data_valid` · `is_adjustment_suspect` · `is_strategy_extreme` ·
  `operationally_safe_for_classification` · `candidate_bucket_research` · `candidate_bucket_operational`.
- **버킷 규칙 개정**:
  - 불가능 데이터 → `invalid_data`
  - 봉 부족 → `insufficient_data`
  - **진짜 조정 의심**(adjusted≠raw 또는 미설명 분할 점프) → `*_raw_needs_adjusted_review`
  - **전략 극단이나 데이터 깨끗** → `A`/`B`(+`strategy_extreme` 경고, operational 가능)
- 분할 의심 판정은 **일일점프>50%**(현 임계 유지)로 한정 — range/gain은 더 이상 단독 하드 블록 아님.
- **테스트 업데이트**: 깨끗-극단 B가 operational 가능 + 진짜 조정의심은 여전히 review + 하드 invalid 유지 검증.
- **검증**: 5종 read-only 재스캔 → **000660/005930가 `B`(strategy_extreme=true, safe=true)** 로 노출되는지 확인,
  035420/005380/051910은 none 유지.
- **불변**: DB write 0 · 라이브 KIS 0 · SignalLog/Trade/Order 0 · 마이그레이션 0 · 스케줄러/디스패처 0. 후보 영속화는
  여전히 별도(M2.15D).
