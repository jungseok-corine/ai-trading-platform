## 1. Purpose

M2.14B-3d(무인 스케줄러 통합) 착수 여부를 결정하기 전, **Go/No-Go 체크리스트**와 **운영 런북**을 확정한다.
디스패처 서비스 코어(3c, 비활성)와 읽기전용 status(3e)까지 와 있으나, **무인 백그라운드 실행은 아직 없다.**
3d는 "스케줄러 잡 1개"를 추가해 무인 실행을 *가능케* 하므로 안전 표면이 질적으로 커진다 — 본 런북이 그 전제
조건·금지선·운영 절차·스모크를 못박는다.

## 5. Future scheduler job contract (구현 없이 정의)

- **잡 이름(제안)**: `RECURRING_PLAN_DISPATCHER_JOB_ID = "recurring_plan_dispatcher"`
  (기존 `*_JOB_ID` 컨벤션). `func = run_recurring_plan_dispatcher_job`.
- **기본 비활성**: `env_enabled = lambda s: s.paper_signal_recurring_plan_dispatcher_enabled`(기본 false).
  IntervalTrigger(예: 60s) but enabled=false이면 미실행.
- **첫 줄 플래그 검사(핵심)**: 잡 함수 본문 첫 줄에서 `get_settings().paper_signal_recurring_plan_dispatcher_enabled`
  확인 → false면 즉시 return(no-op). **이로써 `run_now`로 강제 실행돼도 차단**(우회 위험 봉쇄, D-27/§3 위험).
- **필수 config 게이트**: 코어 `dispatch_due_recurring_plans_once`가 이미 검사 — dispatcher false / KIS real true /
  global runner true → blocked no-op. 잡은 코어를 호출만 한다(중복 평가 경로 신설 금지).
- **no-op 결과 형태**: 코어 결과 객체(`blocked_reason`, `plans_selected=0`, `signals_created=0`,
  `orders_created=0`, `trades_created=0`)를 로깅. 잡은 결과를 만들지 않고 코어 결과를 그대로 기록.
- **batch 상한**: `MAX_DISPATCH_BATCH=50` clamp(잡은 기본 batch=10 등 작은 값 전달).
- **due 선택 소스**: `select_due_for_dispatch`(=`paper_signal_recurring_runs`만, row-lock). PaperSignalSession.active
  스캔 금지.
- **금지 호출 경로**: `run_due_sessions` · 전역 런너 · `SchedulerControlService.run_now`(재사용) ·
  autonomous-jobs run-now · `broker.place_order` · TradeService/OrderService.
- **로깅**: 매 패스 — blocked_reason 또는 (plans_selected/processed/completed/failed/skipped/signals_created).
  구조적 로그(plan_id 목록). last_error 발생 시 WARN.
- **readiness status 갱신**: 잡 등록 후 readiness가 `scheduler_dispatcher_implemented`/`scheduler_job_registered`를
  실제값으로 보고하도록 갱신(읽기 전용 유지). `can_execute`는 여전히 **외부/API 실행** 기준 false 유지(스케줄
  실행은 잡 내부 한정).
- **API 노출 없음 · 프론트 컨트롤 없음**: 잡 실행 트리거 엔드포인트/버튼 미추가.

## 6. Operator runbook (미래 스케줄러 운영)

1. **디스패처 OFF 확인**: `GET /api/v1/paper-signal-recurring-runs/dispatcher/readiness` →
   `config.paper_signal_recurring_plan_dispatcher_enabled=false`, `can_execute=false`. 또는 env에 플래그 미설정.
2. **스케줄러 잡 미등록/미활성 확인**: 스케줄러 health/override에서 `recurring_plan_dispatcher` 미존재 또는
   enabled=false. (3d 전이면 잡 자체가 없음 — registry grep 0건.)
3. **readiness UI 읽기 전용 확인**: 프론트 "디스패처 상태(읽기 전용)" 패널에 실행/토글 버튼 없음, "상태 새로고침"만.
4. **due 계획이 상태일 뿐 확인**: readiness `plan_counts.due_active>0`이어도 자동 실행 안 됨(잡 비활성/미존재).
5. **로컬/dev 한정 활성(명시 승인 후에만)**: dev env에서만 `paper_signal_recurring_plan_dispatcher_enabled=true` +
   스케줄러 override enable. **프로덕션 절대 금지.** KIS_REAL_TRADING_ENABLED·runner는 false 유지.
6. **즉시 정지/비활성(킬스위치)**: 플래그 false로 되돌림(→ 잡 첫 줄에서 no-op) 또는 스케줄러 override disable.
   개별 계획은 `POST .../{id}/stop`으로 active→stopped(이후 due 선택에서 제외).
7. **tick 후 확인 대상**: 잡 로그(blocked_reason/processed/completed/signals_created) · readiness plan_counts ·
   SignalLog 증가량(계획당 ≤2) · `orders_created=0`/`trades_created=0`.
8. **안전/위험 카운트**: 안전 = orders 0·trades 0·계획당 SignalLog ≤2·completed가 max_runs에서 종료.
   위험 신호 = orders/trades >0(절대 발생 불가여야), SignalLog가 계획당 2 초과, due_active가 급증.
9. **due_active 급증 시**: 정상(많은 active 계획이 동시 due). batch 상한으로 패스당 처리량 제한됨 — 위험 아님.
   과하면 플래그 OFF로 정지 후 계획 interval/max_runs 재검토.
10. **with_last_error 증가 시**: 계획별 last_error 확인 → 일시 오류(backoff 후 재시도)인지 영구(세션/버전 소실)인지
    판단. 영구면 해당 계획 stop. 반복 하드 실패는 backoff/`failed` 정책(3d 설계)으로 흡수.
11. **SignalLog가 예상보다 증가 시**: 활성 계획 수 × 패스 횟수 × ≤2 한도 내인지 검증. 초과면 **즉시 플래그 OFF** +
    조사(코어 우회/중복 평가 의심).
12. **Trade/Order 등장 시**: **즉시 전면 정지**(플래그 OFF) + 인시던트. 이 경로는 도달 불가여야 하므로 등장 자체가
    안전 위반 — 코드 회귀 조사, 배포 롤백.
13. **`KIS_REAL_TRADING_ENABLED=true`로 보일 시**: 디스패처 코어가 이미 차단(no-op)하나, 이 플래그는 **사람만**
    바꿔야 하는 불변식 — 의도치 않은 true면 즉시 false 복구 + 인시던트.
14. **프로덕션 배포 전**: 마이그레이션 상태 확인(M2.14A `q1r2s3t4u5v6` 적용) · 3개 플래그 false 확인 ·
    스케줄러 잡 enabled=false 확인 · 스모크(§7) 통과 · 킬스위치 절차 리허설.

## 8. Final recommendation

**판정: GO-ABLE(체크리스트 A 17/17 GREEN), 단 즉시 착수가 아니라 "사람 명시 승인 게이트"를 둔 조건부 진행.**

- A 체크리스트는 전부 GREEN이고 안전 경계가 견고하므로, **기술적으로 3d 착수 자격은 충족**됐다.
- 그러나 3d는 무인 실행을 *가능케* 하는 첫 단계이므로 **기본값으로 진행하지 않는다.** 사람이 이 런북을 읽고
  명시 승인할 때만 착수.
- **가장 작은 안전한 3d 범위(승인 시)**: 스케줄러 잡 1개(`recurring_plan_dispatcher`, **기본 비활성**) +
  잡 함수 첫 줄 플래그 검사 + 코어 호출만. **신규 API/프론트/마이그레이션 없음.** readiness가 잡 등록 상태를
  반영하도록 읽기전용 갱신. §7 스모크 전부 통과 필수.
- **승인이 없으면(권장 기본)**: 일시 정지. 그동안 (a) 수동 tick으로 실제 누적/skip 거동 관찰, (b) M2.14 문서
  통합(M2.13/M2.14D/M2.14B-3 중복 정리), (c) 비교 카드 UI 단순화 — 자동화 없이 가치 추가.
