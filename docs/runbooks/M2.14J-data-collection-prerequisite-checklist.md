# M2.14J — Data Collection Prerequisite Checklist

> 운영/문서 전용. 새 기능 없음 · 런타임/마이그레이션 변경 없음 · 합성 데이터/가짜 SignalLog 없음 ·
> Trade/Order/broker 주문 없음 · 스케줄러/디스패처 활성 없음. **수동 tick 수집을 시작하기 전 환경 준비를 확인**한다.

## 1. Purpose

- **빈 DB에서는 수동 tick 수집을 시작할 수 없다**(Session 1 실패 원인). 이 체크리스트가 [M2.14H](M2.14H-manual-data-collection-quickstart.md)
  사용 *전에* 준비 상태를 확인한다.
- 이것은 **스케줄러 자동화가 아니다**(M2.14B-3d 미승인). **거래가 아니다.**
- 합성/테스트 데이터를 실 운영 증거로 오인하지 않게 막는다.

## 2. Quick decision

- baseline/challenger 세션 = 0 → **중단**(수집 불가).
- 반복 계획 = 0 → **유효한 페어가 생긴 뒤에만** 계획 생성/준비.
- 시세(market data) 접근 불가 → tick은 **skip만**(유용한 SignalLog 안 나옴) 예상.
- 어떤 **Trade/Order 경로**라도 보이면 → **중단**(안전 위반).

## 3. Required environment

- API/UI 사용 시 백엔드 기동 · UI 사용 시 프론트/브라우저 가용.
- dev DB 리비전 `q1r2s3t4u5v6`.
- 플래그 **전부 false**: `KIS_REAL_TRADING_ENABLED` · `paper_signal_session_runner_enabled` ·
  `paper_signal_recurring_plan_dispatcher_enabled`.
- 디스패처 status **읽기 전용** · 스케줄러 잡 **없음** · 디스패처 실행 엔드포인트 **없음**.
- 유용한 SignalLog를 원하면 **(모의)paper 시세 접근** 확보.

## 4. Required data before first manual tick

- baseline paper signal session **1개 이상** · challenger paper signal session **1개 이상**.
- 둘 다 **active** · **같은 종목**.
- challenger `source_type=signal_challenger` · `baseline_session_id`로 baseline 연결.
- 두 전략 버전 **DRAFT** · **auto_trade 비활성**.
- 그 페어에 대한 반복 계획 **1개**(prepared 또는 active).

## 5. Where the data should come from

- **선호(실데이터)**: 상류 파이프라인 산물 — ScannerRule/Version → CandidateEvent →
  승인된 CandidateStrategyProposal → Strategy/StrategyVersion → baseline paper 실험/세션 →
  기존 제안 흐름에서 challenger prepare/activate.
- **UI/dev 워크스루 한정으로만 허용**: 추후 승인된 **명시적 SYNTHETIC/DEMO 부트스트랩**(라벨 필수).
- **거래 증거로 불가**: `tests/_make_pair` fixture · 테스트에서 베낀 직접 DB insert · 가짜 SignalLog row ·
  합성 결과를 실 비교로 제시하는 것.

## 6. Empty DB diagnosis (Session 1 기록)

읽기 전용 프로브(2026-06-29, 변경 0): `total_sessions=0 · signal_challenger=0 · active_challenger=0 ·
recurring_plans=0 · active_plans=0`.

→ **결론: 수동 tick 수집 불가 · 정직하게 모을 유용 표본 없음 · 표본을 날조하지 않는다.**

## 7. Safe readiness probes (읽기 전용만)

> SELECT/count만. **파괴적 명령·reset·purge 금지.**

```python
# READ-ONLY. dev DB 카운트만 — 변경/브로커 호출 없음.
import asyncio
from sqlalchemy import select, func
from app.db.session import async_session_factory
from app.domain.models.paper_signal_session import PaperSignalSession
from app.domain.models.paper_signal_recurring_run import PaperSignalRecurringRun
from app.domain.models.trade import Trade

async def probe():
    async with async_session_factory() as s:
        async def c(stmt): return (await s.execute(stmt)).scalar_one()
        M, R = PaperSignalSession, PaperSignalRecurringRun
        print("sessions", await c(select(func.count()).select_from(M)))
        print("signal_challenger", await c(select(func.count()).select_from(M).where(M.source_type=="signal_challenger")))
        print("active_challenger", await c(select(func.count()).select_from(M).where(M.source_type=="signal_challenger", M.status=="active")))
        print("recurring_plans", await c(select(func.count()).select_from(R)))
        print("active_plans", await c(select(func.count()).select_from(R).where(R.status=="active")))
        print("trades", await c(select(func.count()).select_from(Trade)))
asyncio.run(probe())
```

API 대안(읽기 전용): `GET /api/v1/paper-signal-recurring-runs`(목록) · `GET /api/v1/paper-signal-recurring-runs/dispatcher/readiness`(`plan_counts`).
주문/거래 카운트는 SELECT만으로 확인(주문 API 호출 금지).

## 8. Go / No-Go

**Go (모두 충족 시에만)**: 유효한 baseline/challenger 페어 ≥1 · 그 페어에 반복 계획 선택/생성 가능 · 플래그
전부 false · 스케줄러/잡 없음 · 디스패처 status 읽기 전용 · (유용 SignalLog 기대 시) 시세 접근 가용 ·
운영자가 **"단발 비교"는 누적이 아님**을 알고 **"계획 누적용 1회 기록"**을 쓸 것.

**No-Go (하나라도면 중단)**: DB 비어 있음 · 테스트 fixture만 존재 · 합성/DEMO 데이터뿐인데 실 증거를 원함 ·
시세 불가인데 유용 비교를 기대 · 스케줄러/디스패처 플래그 true · Trade/Order 경로 출현 ·
운영자가 baseline/challenger/계획/tick을 설명 못 함.

## 9. Relation to M2.14H

- **M2.14J = 선행 준비 확인**(이 문서). **M2.14H = 준비 통과 후 실제 수동 tick + 로그.**
- Go면 M2.14H 퀵스타트로 진행. No-Go면 §5의 데이터 출처를 먼저 갖춘다.

## 10. Relation to future bootstrap

- dev/demo 부트스트랩은 추후 유용할 수 있으나 **여기서 구현하지 않음.**
- 별도·명시 승인 필수 · **SYNTHETIC/DEMO 라벨** · 성과/거래 증거 생성 금지 · M2.14B-3d 승인과 무관.

## 11. Relation to M2.14B-3d

- **3d는 여전히 미승인.** 빈 DB라면 자동화 정당성은 **더더욱 없다**(가속할 수동 흐름 자체가 없음).
- 자동화 재고 전 **유용한 수동 표본이 먼저 존재**해야 한다.
