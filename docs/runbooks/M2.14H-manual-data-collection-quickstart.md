# M2.14H — Manual Data Collection Quickstart

> 운영/문서 전용. 새 기능 없음 · 런타임/마이그레이션 변경 없음 · 스케줄러/잡/API 실행/프론트 실행 컨트롤 없음 ·
> 이 문서가 SignalLog/Trade/Order를 만들지 않는다. 목적: **스케줄러 자동화(M2.14B-3d) 결정 전, 운영자가 수동
> tick으로 쓸 만한 데이터를 모으는 법**을 한 장으로 안내.

## 1. 세션 준비(매번)

1. 안전 플래그 false 확인: `KIS_REAL_TRADING_ENABLED` · `paper_signal_session_runner_enabled` ·
   `paper_signal_recurring_plan_dispatcher_enabled`.
2. 스케줄러/잡 없음 확인(디스패처 잡 미등록).
3. UI에서 **"디스패처 상태(읽기 전용)"** 펴서 `실행 가능 여부: 불가` · `스케줄러: 없음` · `자동매매: 아님` 확인.
4. baseline/challenger **페어 1개** 선택(같은 종목·같은 baseline·challenger=signal_challenger·DRAFT 버전).
5. 반복 계획 **1개** 선택 또는 "계획 누적"에서 생성(prepared).

## 2. tick 루틴(1회)

1. 계획이 prepared면 **"수동 기록 가능 상태로 전환"**(active). active만으로는 신호 0건.
2. 선택한 active 계획에 **"계획 누적용 1회 기록"** 1번(= 1 tick). 기준/챌린저 각 ≤1, 총 ≤2 SignalLog.
3. **"신호 성과 비교 보기"** 다시 눌러 비교 갱신 + 표본 힌트 확인.
4. **"상태 새로고침"**(디스패처 status) — completed_runs/카운트 갱신.
5. 아래 로그 1행 기록.

> "단발 비교"(페어 1회 기록)는 계획에 **누적되지 않는다**. 데이터 수집은 반드시 **"계획 누적용 1회 기록"**으로.

## 3. 최소 표본 가이드

- paired(= 두 세션 중 작은 신호 수) 또는 completed_runs 기준:
  - **< 10 → 표본 부족**(판단 금지)
  - **10 ~ 29 → 관찰 중**(초기 관찰만)
  - **>= 30 → 비교 시작 가능**(1차 비교 임계)
- 페어 **1~3개**로 시작, 페어당 **약 30 tick**을 모은 뒤 비교를 신뢰.

## 4. tick마다 기록할 것

날짜/시각 · 종목 · baseline 세션 id · challenger 세션 id · 반복 계획 id · completed_runs(before→after) ·
SignalLog 수(before→after) · 생성/skip 결과 · skip 사유 · next_run_at · last_run_at · 비교 요약 ·
사람 메모(장 상황 / 혼동 / UI 이슈).

## 5. 판단 기준

- **10 미만 표본으로 판단하지 않는다.** 10~29는 초기 관찰, 30+에서 1차 비교.
- 단발 한 번의 좋은 결과보다 **일관성**을 본다.
- challenger가 baseline에 **일관되게 열세**면 승격하지 않는다(승격은 사람·별도 흐름).
- **skip/에러율이 높으면**(중복/장마감/무신호/검증 실패) 자동화 전에 전략/입력을 점검.
- 운영자가 헷갈리면 자동화 전에 **UI/문서를 먼저 고친다**.

## 6. 안전 정지 기준(하나라도 보이면 즉시 중단·조사)

- Trade가 생긴다 · Order가 생긴다 · broker/KIS 주문 호출이 보인다.
- 디스패처 플래그가 예기치 않게 true가 된다 · 스케줄러 잡이 생긴다.
- API 실행 엔드포인트가 생긴다 · 프론트에 실행 버튼이 생긴다.
- **수동 tick 없이** SignalLog 수가 는다 · **수동 tick 없이** completed_runs가 증가한다.

→ 위 중 하나라도면: 작업 중단 · 플래그 false 확인/복구 · 해당 계획 stop · 인시던트로 기록.

## 7. M2.14B-3d 재고 기준(모두 충족 + 사람 명시 승인 시에만)

- 페어 **1개 이상이 30+ 유용한 수동 tick** 보유.
- 운영자가 prepared/active/tick/due/status를 **막힘없이 설명** 가능.
- 디스패처 status UI를 이해함.
- **예기치 않은 row 변경 0**(안전 정지 기준 위반 없음).
- 수동 과정이 **반복적이어서 자동화가 시간을 절약**할 게 분명함(자동화 이득 명확).
- 런북(Go/No-Go) 게이트가 여전히 GREEN.

→ 충족돼도 **자동 승인 아님.** 런북 §7 스모크 + 기본 비활성 + 잡 첫 줄 플래그 검사 + 사람 명시 승인 필요.

## 9. 지금 정리(요약)

- **지금 할 일**: 위 루틴으로 **실제 수동 tick 데이터를 모은다**(페어 1~3개 × ~30 tick).
- **하지 않을 일**: 스케줄러 통합 · 디스패처 활성 · API 실행 라우트 · 프론트 실행 버튼 · 플래그 활성 · 실거래.
- **M2.14B-3d는 미승인 유지** — §7 충족 + 사람 명시 승인 전까지 자동화 없음.
