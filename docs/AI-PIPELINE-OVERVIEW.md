# AI 파이프라인 전체 개요 — 데이터 수집·연구 루프·프론트엔드·계획 대비 갭

> 목적: "AI 부분이 데이터를 **어디서 받아** **어떻게 쓰는지**", "프론트엔드에서 **어디를 보면 되는지**",
> 그리고 "**처음 계획 대비 얼마나 좁혀졌는지**"를 비개발자 기준으로 한 곳에 정리한다.

## 0. 한 줄 철학 (다시 확인)

> **"자동매매보다 자동 실험 시스템을 먼저."**
> AI는 **제안자**다 — 전략/룰을 자동 활성화하지 않고, 실거래를 켜지 않으며, 기존 버전을 덮어쓰지 않는다.
> 모든 자율 잡은 기본 **비활성**, 모든 연구 작업은 **read-only**.

## 1. 데이터를 어디서 받아오나 (수집 레이어)

| 데이터 | 출처/API | 저장 테이블 | 수집 방식(잡) | 기본 | KR | US |
|---|---|---|---|---|---|---|
| **시세(분봉)** | KIS 국내 broker / 해외 overseas | `market_data` | 별도 잡 없음 — **전략 실행기가 신호 낼 때 그때그때 저장** | (러너 60s) | ✅ | ✅ |
| **수급(투자자별)** | KIS 실전 `FHPTJ04160001` | `investor_flows` | `data_refresh` 잡 (매일 16:00) | off | ✅ | ❌ |
| **공시(한국)** | DART `opendart.fss.or.kr` | `news_events`(source=dart) | `dart_ingest` 잡 (10분 간격) | off | ✅ | ❌ |
| **공시(미국)** | — | — | **미구현 (SEC EDGAR 없음)** | — | — | ❌ |
| **뉴스** | DART만(위) + 수동입력 | `news_events` | `dart_ingest` / 수동 API | off | ✅(공시기반) | ❌ |
| **매크로/미장 스냅샷** | FRED(VIX·금리·S&P·나스닥) + Twelve Data(SOX) | `us_market_snapshots` | `us_market_refresh` 잡 (매일 07:00) | off | — | ✅ |

핵심 포인트:
- **시세는 별도 수집 잡이 없다.** 전략 실행기가 종목 신호를 평가할 때 KIS에서 분봉을 받아 `market_data`에 같이 저장한다(그래서 신호가 도는 종목만 시세가 쌓인다).
- **수급은 국장 전용**(KIS 모의는 미지원이라 실전 키 필요). 미장 수급은 KIS에 없다.
- **공시는 한국(DART)만.** **미국 공시(SEC EDGAR 등)는 아직 안 받는다.**
- **"뉴스"라는 독립 소스가 없다.** 지금 뉴스 = DART 공시를 중요도 점수로 거른 것 + 수동입력. 외부 뉴스 API(블룸버그/RSS 등)·**미국 뉴스는 미구현.**
- **매크로는 미장(전일) 기준** — VIX/금리/나스닥/SOX를 받아 "위험선호(risk_on/neutral/risk_off)" 레짐을 분류하고, 그게 스캐너 점수·전략 제안에 반영된다.

## 2. 연구 루프 전체 흐름 (데이터가 어떻게 흐르나)

```
[수집] market_data(시세) + investor_flows(수급)
   │
   ▼
[스캔] ScannerScanService → facts 계산 → 룰 조건 평가 (+매크로 레짐으로 점수 보정)
   │                                   └ market_context_snapshots(시장맥락) 기록
   ▼
[후보] candidate_events  (어떤 종목이 왜 걸렸는지: matched_conditions + facts)
   │
   ▼
[전략/신호] StrategyRunnerService → UniverseResolver(scanner_candidates/watchlist, 시장필터)
   │          → SignalService → signal_logs   (universe 모드는 auto_trade 강제 off = 신호 전용)
   │          → (단일종목 + auto_trade 켠 경우만) trades
   ▼
[AI 분석] DailyAnalysisService (활성 전략별, 활동량 게이트 통과 시)
   │   └ AnalysisBundle(입력 조립) = 신호+체결 요약 + 트레이드테이프(MFE/MAE) + 매크로 + 뉴스 + 회고
   │   └ LLM(Claude/GPT/fake) 단일 또는 듀얼(상호비평+종합) → ai_analysis_runs / ai_model_responses
   ▼
[제안] strategy_proposals / scanner_rule_proposals  (항상 status=PENDING)
   │     ├ AI 분석에서 추출(source=ai_llm) 또는 성과 휴리스틱(source=ai)
   ▼
[사람 승인]  ProposalService.approve  ← 사람만. 승인해도:
   │     · 새 버전은 **항상 DRAFT**
   │     · **auto_trade_enabled=False 강제**
   ▼
[새 버전(DRAFT)] strategy_versions(DRAFT)  → 승격 게이트(판단만, 자동활성 없음)
   │
   ▼
[회고] ProposalRetrospectiveService: 승인된 새 버전 vs 기존 버전 (전략=기대값 / 스캐너=승률)
        verdict: 개선/악화/판단보류  → 다음 AI 분석 번들에 주입(피드백 루프)

[관제탑] GET /research-status: 잡 상태 + 검토 대기 제안 수 + 활성 버전 수 + 회고 요약 + 매크로 + 공시 알림 수
```

### 안전장치(코드로 강제되는 불변식)
1. **universe 모드 = 신호 전용** — auto_trade 강제 off (`strategy_runner_service.py`).
2. **승인해도 auto_trade off + 항상 DRAFT** (`proposal_service.py`).
3. **제안은 항상 PENDING** — AI가 스스로 활성화 못 함.
4. **AI 루프에서 실주문 API 호출 없음.**
5. **새 잡은 기본 off.**

## 3. AI는 구체적으로 무엇을 받아 어떻게 쓰나

**입력(AnalysisBundle)** — 전략 버전 하나당 다음을 모아 LLM 프롬프트로 만든다:
- **신호/성과 요약**: 해당 버전의 최근 신호, 승률·기대값, 최근 체결.
- **트레이드 테이프**: 체결을 압축 + 지표(VWAP 대비/거래량 z-score/MFE·MAE) 사전계산.
- **매크로**: 전일 미장 레짐(risk_on/off).
- **뉴스**: 해당 종목 관련 DART 공시를 중요도로 큐레이션한 것.
- **회고**: (있으면) 이전 제안이 개선/악화였는지 요약 → "악화 많으면 신중" 신호.

**처리(Provider 레이어)**: `fake`(기본, 무호출) / `openai` / `anthropic`. 모드: 단일 또는 **듀얼(GPT·Claude 독립분석 → 상호비평 → 종합)**.

**출력**: `ai_analysis_runs`(런 메타) + `ai_model_responses`(역할별 응답: primary/secondary/critique/synthesis). 분석 텍스트에서 **개선 가설을 파싱**해 `strategy_proposals`(PENDING)로 만든다. **파라미터는 제안에만 담기고 자동 적용되지 않는다.**

> 미장 데이터로도 분석이 되나? — **된다.** 신호 결과(forward return)가 신호의 timeframe(미장 5m)으로 조회되도록 고쳤고(C-5.13), 분석 번들의 종목 시세 요약도 timeframe 무관하게 집계한다. 단, **AI 분석 단위는 `strategy_version`** 이라 한 전략에 KR+US가 섞이면 같이 분석된다 → `universe_market=US`로 **미장 전용 전략을 따로** 두면 분석도 시장별로 갈린다(운영 권장).

## 4. 프론트엔드: 어디서 무엇을 보나 (지도)

상단 탭 **4개**: **대시보드 / 전략 / 관심종목 / 연구 랩(Research Lab)**.

### 대시보드 (실시간 운영)
- 엔진 상태, **자동 실행 로그**(스케줄러 run), **매매 신호**(+신호 결과 보기), 포지션/체결, 포트폴리오, 리스크 컨트롤(긴급정지).
- 수동 버튼: 1회 실행, 주문 동기화, 긴급정지 토글.

### 전략
- 전략 목록(+이름/설명 **수정**), 버전 목록(파라미터/상태 draft→testing→active), 버전 성과 패널.
- **AI 전략 분석 실행 패널** ← 여기서 "AI 분석 실행"(provider·모드 선택) → 결과(개요/리스크/개선) 확인. **AI가 직접 나타나는 첫 번째 자리.**

### 관심종목
- watchlist 목록/종목(+시장 KR/US·거래소), 일괄 전략 생성.

### 연구 랩 (AI 연구 루프의 본체 — 섹션 ~23개)
주요 섹션과 보는 것:
- **운영 개요(Operations)**: 30일 다이제스트 — 안전 점검, 검토 대기 제안, 활성 버전, 승격 가능, 매크로 레짐, 승인율, 회고(개선/악화), AI 비용, 손익.
- **자율 잡 제어판**: 6개 연구 잡 on/off·즉시 실행.
- **파이프라인 / 시장맥락 / 차트**: 잡 실행 상태, **DART 공시 알림**, 레짐/섹터 강도, 버전별 캔들+신호 마커.
- **스캐너**: 룰/버전/조건 정의, 시장 스캔 실행.
- **후보(Candidates)**: 스캐너가 잡은 종목 + 점수/근거 + (옵션)회고. 후보→전략 **배정**.
- **배정/실험**: 배정 규칙·로그, 챔피언/챌린저 A/B 비교.
- **AI 제안(전략/스캐너)** ← **AI가 나타나는 핵심 자리.** 제안 목록(근거/기대효과/리스크/파라미터 diff) → **승인/거절**. 승인 = 새 DRAFT 생성(자동활성 아님).
- **회고/퍼널/승격 준비**: 승인 제안이 실제로 개선됐는지, 제안 깔때기, 승격 기준 충족 버전.
- **승격 게이트**: 기준 정의·평가(판단만, 자동 활성 없음).
- **일일 리포트**: 시장별(KR/US) 신호·체결·후보·제안 집계.
- **안전/비용/감사/신선도**: 불변식 점검, AI 토큰·비용, 분석 감사 로그, 데이터 신선도.
- **거래활동/운영추세/리스크이벤트/포트폴리오**.

**"AI"가 실제로 보이는 곳 4군데**
1. 전략 페이지 **AI 분석 실행 패널**(분석 돌리기).
2. 연구 랩 **AI 제안** 섹션(제안 보고 승인/거절).
3. 연구 랩 **스캐너 제안** 섹션.
4. 연구 랩 **회고** 섹션(제안이 도움이 됐는지 → 다음 분석에 반영).

> 비개발자 관점 혼란 포인트: 연구 랩 섹션이 너무 많고(23개), "후보/배정/실험/제안/회고/승격"이 한 흐름인데 탭으로 흩어져 보인다. **실제 흐름은: 스캔→후보→(배정/실험)→AI제안→승인→회고→승격** 순서다.

## 5. 처음 계획 대비 갭 분석 (planned vs built)

기준 문서: `CLAUDE.md`(철학), `ROADMAP.md` §1 비전/§2 연구루프/§7 AI 파이프라인 설계/§7.1 인트라데이 감시, `mvp-plan.md`, `revised-architecture.md`, `ai-analysis-workflow.md`, `risk-management.md`.

### ✅ 계획대로 달성한 것
- **연구 루프 전체**(수집→스캔→후보→배정→실험→AI제안→승인→DRAFT→승격→회고) — 구축 완료.
- **AI=제안자 불변식** — 코드로 강제(PENDING/DRAFT/auto_trade off). 안전 불변식 테스트 존재.
- **AI 분석 듀얼모델**(GPT·Claude 독립→상호비평→종합) + 비용 게이트 + provider 추상화(fake 기본).
- **리스크 레이어**(6룰, RiskManager는 DB 무접근, 모든 판정 로깅).
- **매크로 인지**(FRED+TD, 레짐 분류 → 스캐너 점수·전략 제안 반영).
- **DART 공시 + 중요도 큐레이션**(+옵션 LLM 정밀화).
- **멀티마켓(미국장)** — 시세/주문(모의)/체결동기화/세션/USD 환산/시장 분리 리포트까지(C-5).
- **운영 콘솔/관제탑**(비용·퍼널·안전·신선도·다이제스트).

### ⚠️ 계획에 있었지만 아직 안 된 것 (갭)
| 항목 | 원래 계획 | 현재 |
|---|---|---|
| **미국 공시** | (멀티마켓 맥락상 기대) | **미구현** — SEC EDGAR 등 없음. 공시는 한국 DART만. |
| **미국 뉴스 / 외부 뉴스 소스** | "중요 뉴스 큐레이션" | **미구현** — 뉴스 = DART 공시 기반만. 외부 뉴스 API 없음. |
| **인트라데이 이벤트 감시(§7.1)** | 보유종목 실시간 공시/뉴스 폴링 → 싼 모델 큐레이션 → 알림 | **✅ 1차 구현(C-5.17)** — 보유/활성 종목 한정 장중 DART 폴링 잡 + 보유종목 알림. (남은 것: 온디맨드 AI 평가 자동 트리거, 미국 공시) |
| **백테스팅 엔진** | 2차 목표로 명시 | **미구현(보류)** — 대신 신호 forward-return(회고)으로 대체 중. |
| **AI 분석 시장 분리** | (멀티마켓 후속) | **부분** — 분석 단위가 strategy_version. `universe_market`로 운영상 분리 가능하나 구조적 시장 그룹핑은 미완. |

### ⏸️ 원래부터 "의도적 보류"였던 것 (갭 아님)
- **실거래** — 안전 불변식상 off 유지(페이퍼 검증 후 사람만).
- **NXT·미장 확장시간 "주문"** — KIS 모의 미지원, 실거래 전용.
- **US 실시간 분봉/틱** — KIS 승인 또는 Polygon 유료(현재 EOD/분봉으로 충분).
- **Celery / Redis / WebSocket / TimescaleDB** — 규모 커지면. MVP는 APScheduler/폴링/Postgres로 의도적 단순화.
- **Mac mini 배포 / SOX 직접지수** — 자원·라이선스 준비되면.

### 한 줄 결론
> **연구 루프와 AI 제안·승인·회고의 "뼈대와 안전장치"는 원래 계획대로 거의 다 구현됐다.**
> 가장 큰 실질 갭은 **(1) 미국 공시·뉴스 수집이 없다**는 점과 **(2) 보유종목 실시간 이벤트 감시 루프(§7.1)가 미완**이라는 점.
> 그 외(백테스트 엔진, Celery 등)는 원래 후순위/보류로 합의됐던 항목이다.
