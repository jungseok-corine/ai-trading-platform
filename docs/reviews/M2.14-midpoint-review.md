## 1. Executive summary

baseline↔challenger paper 신호 비교 도구는 **수동 흐름(M2.14A~E)이 완성**되고, 무인 디스패처는
**설계(3a)→읽기 readiness(3b)→비활성 서비스 코어(3c)** 까지 왔다. 현재 디스패처 코어는 존재하지만
**기본 비활성·비스케줄·비노출·테스트 직접 호출 전용**이라 런타임에서 무인 실행이 불가능하다.

**판정: ON TRACK(경미한 정리 권고).** 안전 경계는 견고하고(실거래/주문/거래/스케줄/노출 전부 도달 불가),
복잡도는 대부분 안전 요구에서 비롯된 정당한 것이다. 단, **3d(스케줄러 통합) 직행은 권하지 않는다** —
먼저 안정화 체크포인트(읽기전용 프론트 status 또는 문서 정리)를 두고, 별도 명시 승인 + 엄격한 게이트로만
진행한다. 본 리뷰는 **3d를 승인하지 않는다.**

## 4. Current architecture (first-time developer 설명)

1. **Strategy proposal(전략 제안)**: AI 분석이 만든 전략 변경안. 항상 `pending`으로 시작, 사람이 승인해도
   `DRAFT + auto_trade=False`(안전 불변식).
2. **Challenger strategy/session**: baseline 전략의 변형(challenger). 같은 종목·같은 baseline에 묶여 공정
   비교 대상이 된다. challenger 세션은 `source_type="signal_challenger"`.
3. **Paper signal session**: 한 전략 버전으로 신호(SignalLog)를 기록하는 모의 세션. 주문/체결 없음.
4. **Recurring signal plan**: 한 (baseline, challenger) **페어**에 대해 반복 신호 기록을 *계획*하는 행
   (`paper_signal_recurring_runs`). interval/max_runs/completed_runs/next_run_at 메타데이터.
5. **prepared**: 계획이 만들어졌지만 **inert**(next_run_at NULL). 아무 신호도 안 생긴다.
6. **active(="수동 기록 가능")**: tick 후보 상태. **실행이 아니다** — 이 상태만으로는 신호 0건.
7. **manual tick-once**: 사람이 plan_id 하나를 골라 confirm한 **1회** 평가. baseline/challenger 각 ≤1
   (총 ≤2) SignalLog. 디스패처 아님.
8. **dispatcher readiness**: 디스패처 가용성/카운트를 **읽기 전용**으로 보고하는 API. 아무것도 실행 안 함.
9. **dispatcher service core**: due active 계획을 1패스 처리하는 내부 코어. **기본 비활성·비스케줄·비노출·
   테스트 직접 호출 전용.** 실행 시 `tick_plan_once` 코어를 재사용.
10. **아직 미구현**: 스케줄러 통합(3d) · 디스패처 실행 API/프론트 컨트롤(3e) · 프로덕션 활성 · 실거래/주문.

플로우:
```
분석 리포트 → pending 제안 → draft challenger → prepared challenger 세션 → active challenger 세션
  → (페어 run-once  또는  recurring plan)
  → 수동 tick  /  비활성 디스패처-코어 테스트 직접 호출
  → SignalLog 누적
  → 비교/성과 리뷰
  → Trade/Order 없음
```

## 6. Complexity / drift review (비판적)

1. **원래 목표에서 드리프트했나?** — **아니오.** 여전히 "AI가 실험, 사람이 승인"의 paper 신호 연구/비교
   도구. 자동매매로 새지 않았다.
2. **M2.14가 너무 무거워졌나?** — **다소.** 13개 하위 단계는 많지만, 각 단계가 작고 사람 게이트 1개씩
   추가하는 방식이라 개별 리스크는 낮다. "무거움"은 단계 수이지 결합도가 아니다.

4. **필수 부분** — recurring 스키마 · tick 코어(D-26) · 안전 게이트 · row-lock 선택 · readiness 가시성.

6. **여전히 혼동 가능한 UI** — 세 "1회 기록"(단발/계획 누적/디버그)은 M2.14E로 라벨 구분했으나 한 카드에

## 11. Final verdict

**ON TRACK — 단, 자동화 추가 전 일시 정지(human checkpoint) 권고.**

이유: (1) 안전 불변식이 모든 단계에서 보존됨(실거래/주문/거래/스케줄/노출 전부 도달 불가, 플래그 기본
false). (2) 복잡도는 단계 수에서 오지만 결합도/리스크는 낮고 대부분 안전 요구로 정당화됨. (3) 무인 실행을
켜는 스위치(스케줄러 잡)가 아직 없어 현재 상태는 본질적으로 안전. (4) 다음 단계(3d)는 안전 표면이 질적으로
