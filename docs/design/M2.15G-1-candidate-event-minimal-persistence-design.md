# M2.15G-1 CandidateEvent Minimal Persistence Design

> **설계 문서만.** 코드 구현 0 · migration 0 · DB schema 변경 0 · CandidateEvent 모델/테이블/저장 API 0 ·
> DB write 0 · 외부/KIS 호출 0 · SignalLog/Trade/Order 0 · 스케줄러 0 · frontend 0.
> **CandidateEvent는 매수 신호가 아니다.**

## 1. Purpose

CandidateEvent는 매수 신호가 아니다. 특정 시점에 **research-only leader trend candidate가 관찰되었다는 사실**을
기록하는 연구 이벤트다.

기록 목적:
- 후보 발생 이력 저장
- 후보 이후 성과 추적
- 후보 타입 A/B/none과 이후 수익률 비교
- AI 분석/전략 평가에 사용할 ground truth 축적
- 실거래와 분리된 연구 데이터셋 구성

## 2. Non-goals (명확히 금지)

실거래 · 주문 생성 · Trade 생성 · SignalLog 생성 · StrategyRunner 연결 · scheduler 자동 실행 · 자동 추천 ·
매수/매도 판단 · AI 자동 의사결정 · full-universe 확장 · 20/110 확장 · CandidateEvent 기반 자동 알림.

## 3. Current Readiness

- **F-1** non-KIS validation harness — done
- **F-2** manual reference snapshot 분리 — done
- **F-3A** DB 52W snapshot endpoint — done
- **F-3E** Naver validation — done (matched 0 · minor_diff 3 · major_diff 2)

## 4. CandidateEvent Minimal Data Model Proposal

최소 필드:
- `id`
- `symbol`
- `detected_at`
- `reference_date`
- `timeframe`
- `universe_scope`
- `scanner_name`
- `scanner_version`
- `candidate_bucket` (A | B | none)
- `is_operational_candidate`
- `strategy_extreme`
- `current_price`
- `low_52w`
- `high_52w`
- `low_52w_gain_pct`
- `drawdown_from_52w_high_pct`
- `window_basis` (last_252_trading_rows | calendar_52_weeks | source_reported)
- `data_source` (local_market_data)
- `validation_source` (naver_manual)
- `validation_status` (matched | minor_diff | explained_major_diff | unresolved_major_diff | not_validated)
- `validation_report_path`
- `research_only`
- `not_buy_signal`
- `created_at`

선택 필드: `notes` · `source_basis_note` · `provenance_warning` · `safety_warning`.

**주의(FK 금지):** Order/Trade/SignalLog FK 금지 · broker/KIS FK 금지 · strategy runner FK 금지 · 초기 버전에서
StrategyVersion FK도 신중 검토. **후보 이벤트는 strategy execution record가 아니라 research observation record다.**

## 5. Uniqueness / Idempotency

권장 unique key: `(symbol, scanner_name, scanner_version, reference_date, timeframe, window_basis, universe_scope)`.

검토:
- 하루에 같은 symbol이 여러 번 후보로 탐지될 경우 처리 방식.
- 같은 날 재계산 시 **upsert 금지 또는 read-before-create**.
- 최초 구현은 **명시적 manual save만** 허용.
- **scheduler 자동 저장 금지.**

## 6. Allowed Side Effects

M2.15G-2 구현 시 허용: CandidateEvent table insert · CandidateEvent read API · CandidateEvent list API.

금지: Order/Trade/SignalLog 생성 · StrategyVersion 변경 · StrategyRunner 실행 · broker/KIS 호출 · scheduler enable ·
AI 자동 분석 실행 · notification 생성 · portfolio/account 변경.

## 7. API Design Proposal

Read-only first:
- `GET /api/v1/candidate-events`
- `GET /api/v1/candidate-events/{id}`

Manual explicit create only:
- `POST /api/v1/candidate-events/research-only`

POST 조건:
- body에 `research_only=true` · `not_buy_signal=true`.
- candidate source는 existing local candidate result여야 함.
- `validation_status="unresolved_major_diff"`면 **기본 reject**.
- `explained_major_diff`는 허용 가능하나 **`source_basis_note` 필수**.
- scheduler/system auto-create 금지 · **explicit user/API call only**.

→ **아직 구현하지 않는다. 설계만.**

## 8. Safety Gates Before Implementation (M2.15G-2 전 필수)

- CandidateEvent가 Order/Trade/SignalLog와 분리되어 있음.
- migration 설계 리뷰 완료.
- unique key 확정.
- validation_status policy 확정.
- window_basis 필드 확정.
- explained_major_diff 허용 여부 확정.
- CandidateEvent 저장이 매수/추천으로 오해되지 않도록 API/UI warning 확정.

## 9. Testing Plan (구현 시)

- CandidateEvent 생성 시 `research_only=true` 필수 · `not_buy_signal=true` 필수.
- `unresolved_major_diff` reject.
- `explained_major_diff`는 `source_basis_note` 없으면 reject.
- duplicate candidate reject.
- Order/Trade/SignalLog 생성 없음 · broker/KIS 호출 없음 · scheduler untouched.
- DB write는 CandidateEvent insert만 허용.
- CandidateEvent read/list 정상.
- migration upgrade/downgrade 가능.
- full backend pass.
