# M2.14B-3 — Pair-Scoped Recurring Signal Dispatcher Design

> **설계/문서 전용.** 디스패처 구현 없음 · 백엔드 런타임/마이그레이션/엔드포인트/잡/프론트 변경 없음 ·
> SignalLog/Trade/Order 생성 없음 · broker/KIS·`run_due_sessions`·autonomous run-now·`run_now`·`list_active`
> 미사용. 본 문서는 "**만약** 나중에 구현한다면" 전제의 설계일 뿐, 구현 승인이 아니다.
>
> 선결 정책: 디스패처는 **별도 명시 승인 + 비활성 기본 플래그**가 있어야 착수한다(아래 §13).

---

## 1. Current state

manual 흐름은 M2.14A~E로 완성됐다(읽기/검토만으로 확인):

- `paper_signal_recurring_runs` 스키마(M2.14A): `status` · `interval_seconds` · `max_runs` ·
  `completed_runs` · `last_run_at` · `next_run_at` · `last_error` · baseline/challenger FK ·
  CheckConstraints(interval>0, max_runs>0, completed_runs≥0, baseline≠challenger). 인덱스 5종 — 그중
  **`ix_psrr_status_next_run_at(status, next_run_at)`가 due-plan 선택용으로 이미 존재**.
- 서비스 `PaperSignalRecurringRunService`(M2.14A/B-1/B-2): create_prepared / activate / **tick_plan_once** /
  stop / get / list. tick은 M2.8 `evaluate_session`(주입된 signal-only SignalService) 재사용 — 단일 커밋.
- API 6종(create/list/get/activate/tick-once/stop). **run-all·run-due·dispatcher 엔드포인트 없음.**
- 프론트(M2.14C/E): 사람 클릭 전용 UI, active="수동 기록 가능", next_run_at="다음 기준 시각(자동 실행 아님)".
- 결정: D-24(전역 런너 V1 아님) · D-25(활성화≠실행) · D-26(수동 tick≠디스패처).

핵심 재사용 자산: `tick_plan_once`의 **검증→평가→메타데이터 갱신→단일 커밋** 코어(D-26 의미론). 디스패처는
이 코어를 **선택 루프로 감싸기만** 하면 되고, 새 실행 경로를 만들지 않는다.

## 2. Non-goals (이 작업이 하지 않는 것 · 디스패처가 영원히 하지 않을 것)

- 디스패처/스케줄러/잡 구현·활성, 마이그레이션, 엔드포인트, 프론트 — **이번엔 전부 안 함**.
- 디스패처가 구현되더라도 영구 금지: Trade/Order 생성 · `broker.place_order` · KIS 주문 TR ID ·
  실거래(`KIS_REAL_TRADING_ENABLED`는 항상 false) · 전역 `paper_signal_session_runner` 사용/활성 ·
  `run_due_sessions`(전체 active 세션 스캔) · `SchedulerControlService.run_now`(아래 §3 우회 위험) ·
  autonomous-jobs run-now · `PaperSignalSession.list_active` 실행 경로 · auto_trade 켜기.

## 3. Current safety baseline (런타임 불변식 — 디스패처가 보존해야 함)

- create/activate/stop → SignalLog 0. tick → 최대 2 SignalLog(선택 페어만, 제3 세션 무영향).
- 디스패처/스케줄러/잡 없음 · run-all/run-due 엔드포인트 없음 · 전역 런너 비활성.
- autonomous-jobs run-now 미사용 · `run_due_sessions` 미사용 · `list_active` 실행 미사용.
- Trade/Order 도달 불가 · `broker.place_order` 미호출 · `KIS_REAL_TRADING_ENABLED=false` ·
  `paper_signal_session_runner_enabled=false`.

> **⚠ `SchedulerControlService.run_now` 우회 위험(코드로 확인):** `run_now(job_id, app)`은
> `await job.func(app)`를 **직접 호출**해 enabled 플래그를 우회한다(`scheduler_control_service.py:113-117`).
> 따라서 디스패처는 이 경로를 절대 재사용하지 않는다 — 디스패처 잡은 자기 전용 플래그를 **잡 함수 본문 첫 줄에서**
> 직접 검사해야 한다(run_now로 강제 실행돼도 플래그 false면 즉시 no-op 반환).

## 4. Dispatcher risk analysis

| # | 리스크 | 완화 설계 |
|---|--------|-----------|
| 1 | 무인 SignalLog 증가 | tick당 ≤2 · batch 상한 · max_runs 종료 · 플래그 OFF 기본 |
| 2 | 여러 active 계획 동시 due | batch 상한(예 10) · 초과분은 다음 패스 |
| 3 | active 스캔이 너무 광범 | **`paper_signal_recurring_runs`만** 스캔(세션 스캔 금지) |
| 4 | 디스패처 런 간 race | row-lock `FOR UPDATE SKIP LOCKED` · 단일 인스턴스 가정 명문화 |
| 5 | manual tick와 디스패처 tick race | 동일 row-lock 경로 공유 → 동일 plan 동시 tick 불가 |
| 6 | 장마감/stale 반복 skip | skip도 시도이므로 +1(D-26) → max_runs로 자연 종료 · backoff로 빈도 제어 |
| 7 | 전략 에러 반복 | `last_error` 기록 · 연속 실패 임계 후 `failed`(스키마 지원 시) · backoff |
| 8 | max_runs 미정지 | tick 코어가 이미 `completed_runs>=max_runs`→422/`completed` 처리(재사용) |
| 9 | in-flight 중 stop | row-lock + 커밋 경계로 원자화 · stop은 즉시 후속 tick 차단 |
| 10 | next_run_at 의미 모호 | "다음 **기준** 시각" — 디스패처 ON일 때만 due 트리거, OFF면 무의미 메타데이터 |
| 11 | 전역 런너 경로 오용 | D-27로 금지 명문화 · 디스패처는 전용 코어만 호출 |
| 12 | 사용자가 자동매매로 오해 | 읽기전용 UI에 "자동매매 아님/주문 없음/SignalLog만" 배지 유지 |
| 13 | 미래 Trade/Order 연결 사고 | 코어가 signal-only SignalService만 주입(주문 서비스 미구성) |
| 14 | 관측성 공백 | last_run_at/last_error/completed/status 노출 + 구조적 로그 |
| 15 | 롤백/킬스위치 | 플래그 OFF = 즉시 전면 정지 · 개별 stop = 계획 단위 정지 |

## 5. Option comparison

| 옵션 | 내용 | 평가 |
|------|------|------|
| A | 디스패처 영구 차단, 수동 tick만 | 가장 안전, 데이터 축적 느림 |
| B | 선택-계획 수동 tick만(=현재) | 안전한 현 상태, 무인 아님 |
| **C** | **`paper_signal_recurring_runs`만 스캔하는 pair-scoped 디스패처** | **권장 미래 방향**(승인+신중 구현 시) |
| D | 기존 전역 `paper_signal_session_runner` 활성 | **거부(V1 아님)** — 전체 active 세션 실행 · run_now 우회 위험 · D-24 위배 |

**권장: Option C만, 그것도 별도 명시 승인 후.** Option D는 첫 recurring V1로 **영구 금지**(D-27).

## 6. Recommended architecture (future, not implemented)

- **비활성 기본 디스패처 잡 1개.** 잡 함수 첫 줄에서 전용 플래그 + 안전 게이트 검사 → 실패 시 즉시 no-op.
- 스캔 대상: **`paper_signal_recurring_runs`만.** `PaperSignalSession.active` 직접 스캔 금지 ·
  `run_due_sessions`/전역 런너/`run_now`/autonomous run-now 미호출.
- 선택 조건(§7): `status=='active'` AND `next_run_at <= now` AND `completed_runs < max_runs`.
- **M2.14B-2 `tick_plan_once` 코어 재사용** — 새 평가 경로 신설 금지. 디스패처는 "선택→코어 호출→다음" 루프뿐.
- 패스당 **bounded batch**(예 10 plans). SignalLog는 기존 선택-페어 `evaluate_session` 경로로만.
- **Trade/Order 절대 생성 안 함.**

### 필요한 미래 config(구현 승인 시에만 추가)

- 신규 `paper_signal_recurring_plan_dispatcher_enabled: bool = False`(기본 OFF, 별도 플래그).
- 기존 `paper_signal_session_runner_enabled`는 **분리 유지 + false**(디스패처가 이 값을 읽거나 켜지 않음).
- 디스패처 tick에서도 `KIS_REAL_TRADING_ENABLED=false` 필수(true면 tick 차단).

## 7. Plan selection & locking design

### 선택 규칙

- `status == 'active'`
- `next_run_at IS NOT NULL` AND `next_run_at <= now()`
- `completed_runs < max_runs`
- batch size 상한(예 10) · `ORDER BY next_run_at ASC`(가장 오래 due된 것 우선)
- 인덱스: 기존 `ix_psrr_status_next_run_at(status, next_run_at)` 그대로 활용 — **추가 인덱스 불필요**.

### 잠금/중복 방지

- **마이그레이션 없는 1안(권장 시작):** 선택 쿼리에 `SELECT ... FOR UPDATE SKIP LOCKED`(Postgres 지원) —
  두 디스패처 패스·manual tick이 동일 row를 동시에 잡지 못함. tick 코어의 단일-커밋 경계가 원자성 보장.
  manual tick 경로도 동일 row-lock을 타도록 코어를 한 곳으로 모으면 디스패처↔수동 race도 닫힌다.
- **마이그레이션 필요 2안(승인 시):** `running`/`locked_at` 상태 컬럼 추가(가시적 in-progress, 크래시
  복구용 stale-lock 타임아웃). **이는 별도 마이그레이션 + 명시 승인 필요** — 지금 만들지 않는다.
- 단일 디스패처 인스턴스 가정을 문서화(다중 워커면 row-lock 필수). stop 중 in-flight는 row-lock + 커밋
  경계로 안전 처리(stop이 lock을 얻으면 tick은 SKIP, tick이 lock 보유면 stop은 그 커밋 후 적용).

> 결론: **V1은 row-lock(SKIP LOCKED)만으로 무마이그레이션 구현 가능.** `running`/`locked_at`/실패카운트
> 컬럼은 관측성·크래시복구를 위한 **선택적 후속 마이그레이션**(별도 승인).

## 8. Tick semantics under dispatcher

manual tick-once(D-26)와 **동일 의미론**을 그대로 사용:

- `completed_runs`는 **페어 tick 시도 횟수**(SignalLog 수 아님). 양쪽 skip(중복/장마감/무신호)이어도 +1.
- 평가 전 검증 실패/예외는 **+0**(커밋 전 예외 → 롤백).
- `max_runs` 도달 시 `status=completed` + `next_run_at=NULL`. 아니면 active 유지 + `next_run_at` 갱신.
- 실행 시점 재검증 필수(`_load_and_validate_pair`로 M2.8/M2.10 검증 재사용 — 활성화 후 세션/버전 변동 대비).
- stop된 계획은 디스패처 tick 대상에서 제외(선택 조건이 active만).
- 세션/버전/제안 status 불변(세션 카운터만).

## 9. Error / backoff design

| 상황 | 거동 |
|------|------|
| 장마감/stale 데이터 | skip(+1 시도) · backoff로 다음 due 미룸 · tight loop 금지 |
| 중복 캔들 | skip(+1) |
| 무신호 | skip(+1) |
| 일시적 candle/broker 조회 에러 | tick 미커밋(+0) · `last_error` 기록 · backoff 후 재시도 |
| 전략 config 에러 | `last_error` 기록 · 연속 실패 임계 후 `failed`(스키마 지원 시) |
| 활성화 후 세션/버전 소실 | 재검증 실패 → +0 · `last_error` · 사람이 stop |
| `auto_trade` 우연히 true | 전역 게이트에서 차단(tick 거부) |
| `KIS_REAL_TRADING_ENABLED=true` | 디스패처 tick **차단**(게이트 실패 → no-op) |
| `paper_signal_recurring_plan_dispatcher_enabled=false` | 디스패처 잡 **즉시 no-op**(첫 줄 검사) |
| `paper_signal_session_runner_enabled=true` | 디스패처와 무관 분리 — 안전하게 차단/실패(디스패처가 이 경로를 안 탐) |

원칙: **tight loop 금지 · `last_error` 가시 · 반복 하드 실패는 임계 후 `failed`(실패카운트 저장이 필요하면
마이그레이션 요건으로 문서화) · backoff(예: 실패 시 next_run_at = now + interval×k).**

## 11. Test plan (future implementation)

**Selection:** due active 선택 · 미-due active skip · prepared/stopped/completed/failed skip ·
`completed_runs>=max_runs` skip/completed · batch 상한 준수 · `paper_signal_recurring_runs`만 스캔 ·
`PaperSignalSession.list_active` 미호출(스파이/모킹으로 보장).

**Execution:** due 계획 1회 tick · plan당 ≤2 SignalLog · 제3 세션 무영향 · completed_runs +1 ·
last_run_at 설정 · next_run_at 갱신 · max_runs→completed · stopped 미tick · 검증실패 +0 · skip 거동 문서화.

**Safety:** `KIS_REAL_TRADING_ENABLED=true`→tick 차단 · dispatcher 플래그 false→실행 안 함 ·
`paper_signal_session_runner_enabled=true`→차단/안전 실패 · Trade/Order 0 · `broker.place_order` 미호출 ·
전역 `run_due_sessions` 미호출 · `run_now` 미호출 · autonomous run-now 미호출 · `list_active` 실행 미호출.

**Concurrency:** 겹치는 디스패처 패스에서 동일 plan 중복 tick 없음 · manual tick↔디스패처 tick 이중카운트
없음 · pending tick 중 stop 안전.

**Observability:** 실패 시 last_error 설정 · warnings 반환/로그 · completed/failed 가시 · 비교가 누적
SignalLog 반영.

**Compatibility:** M2.14B-2 수동 tick · M2.14C/E UI · M2.10 pair run-once · M2.8 single run-once 모두 유지.

## 13. Explicit blockers before implementation

1. 사용자의 **명시적 디스패처 구현 승인**(설계 통과 ≠ 구현 승인).
2. 신규 `paper_signal_recurring_plan_dispatcher_enabled=false` 기본 플래그 도입 합의.
3. 전역 `paper_signal_session_runner`는 분리·비활성 유지 합의(D-27).
4. row-lock(SKIP LOCKED) 동시성 전략 수용 — 또는 `running`/`locked_at` 마이그레이션 별도 승인.
5. backoff/실패 임계 정책 확정(실패카운트 저장 시 마이그레이션 요건 명시).
6. 단계별(3a→3e) 진행 + 각 단계 push-후 스모크 합의.

## 14. Final recommendation

- **Option C(파일 스코프 = `paper_signal_recurring_runs`만 스캔하는 디스패처)** 를 미래 방향으로 채택하되,
  **지금은 구현하지 않는다.** 다음 안전 작업은 **설계 리뷰** 또는 **M2.14B-3b(읽기 status API only)** 같은
  최소 안전 단계뿐.
- **Option D(전역 런너 활성)는 영구 거부** — D-27로 명문화.
- 디스패처는 **항상 SignalLog-only**, 별도 비활성 기본 플래그, `KIS_REAL_TRADING_ENABLED=false` 불변.
- readiness 체크리스트는 13/13(M2.14E)이지만 이는 **수동 UX 명확성** 기준일 뿐 — **디스패처 구현 승인과는
  별개**다.

## 15. M2.14B-3b — Read-only readiness API (구현됨, 실행 없음)

M2.14B-3b는 디스패처로 가는 **첫 구현-인접 단계이지만 실행은 전혀 하지 않는다.** 어떤 계획도 tick하지 않고,
스케줄러 잡을 등록하지 않으며, SignalLog/Trade/Order를 만들지 않는다. **이 단계는 디스패처 실행을 승인하거나
구현하지 않는다.**

- 엔드포인트: `GET /api/v1/paper-signal-recurring-runs/dispatcher/readiness`(읽기 전용 · body/confirm 없음).
  정적 라우트를 `/{plan_id}`보다 먼저 등록해 plan_id로 파싱되지 않게 한다.
- 신규 플래그 `paper_signal_recurring_plan_dispatcher_enabled=false`(기본 OFF) — **잡/실행에 미연결**.
  True여도 `can_execute=false`(실행 미구현). 전역 런너 플래그와 분리·false 유지.

### 응답 필드 의미

- `dispatcher_stage="readiness_api_only"` · `dispatcher_implemented=false` · `scheduler_job_registered=false` ·
  `can_execute=false` · `execution_blocked_reason="dispatcher_execution_not_implemented"`.
- `config`: 3개 플래그(dispatcher/runner/kis_real) 현재값(보고용).
- `plan_counts`: `total` 및 status별(prepared/active/stopped/completed/failed) + active 하위 **상호 배타**
  분류 `due_active`(active·next_run_at≤now·미소진) / `not_due_active`(active·next_run_at>now·미소진) /
  `active_missing_next_run_at`(active·next_run_at NULL·미소진) / `active_exhausted`(active·completed≥max) +
  `with_last_error`.
- `readiness_blockers`: `["dispatcher_execution_not_implemented","scheduler_job_not_registered"]`.
- `safety_invariants`: scans_recurring_runs_only / global_runner_forbidden / signal_log_only_future_requirement /
  orders_forbidden / trades_forbidden / broker_kis_forbidden(전부 true — 미래 요건 표식).
- `warnings`: "read-only", "no plans are ticked", "no SignalLog/Trade/Order".

### 읽기 전용 보장

- repo `readiness_counts(now)`는 `count(*) FILTER(WHERE …)` 집계만 — **row 변경 0 · row-lock/FOR UPDATE/
  SKIP LOCKED 미사용**(동시성 잠금은 실행 단계 3c+에서만 도입). 서비스 `dispatcher_readiness()`는
  tick_plan_once/evaluate_session/generate_and_log_signal/scheduler를 호출하지 않는다(테스트 스파이로 보장).
- 다음 단계 **3c(비활성 코어 + 테스트 직접 호출, 잡 없음)** 는 별도 명시 승인 후에만.

## 16. M2.14B-3c — Disabled-by-default dispatcher service core (구현됨, 직접 호출 전용)

M2.14B-3c는 디스패처 **서비스 코어의 첫 실행 단계**다. 그러나 **스케줄러/잡/API/프론트에 연결되지 않으며,
서비스 테스트가 직접 호출할 때만** due active 계획을 처리한다. 프로덕션 디스패처 활성/노출은 아직 없다.

### 서비스 코어

- `PaperSignalRecurringRunService.dispatch_due_recurring_plans_once(now=None, batch_limit=10,
  triggered_by="dispatcher_test")`.
- batch_limit은 `[1, MAX_DISPATCH_BATCH=50]`로 clamp(무인 폭주 방지).
- **안전 게이트(선택/실행 전):** `paper_signal_recurring_plan_dispatcher_enabled=false`→no-op
  (`blocked_reason="dispatcher_disabled"`) · `KIS_REAL_TRADING_ENABLED=true`→`real_trading_enabled` ·
  `paper_signal_session_runner_enabled=true`→`global_runner_enabled`. 차단 시 선택/실행/SignalLog/Trade/Order 0.

### 선택 + row-lock

- repo `select_due_for_dispatch(now, limit)`는 **`paper_signal_recurring_runs`만** 스캔(D-27 —
  `PaperSignalSession.active`/`run_due_sessions`/`list_active` 미사용). due = `status=active AND
  next_run_at IS NOT NULL AND next_run_at<=now AND completed_runs<max_runs`. `ORDER BY next_run_at ASC, id ASC`
  LIMIT + **`with_for_update(skip_locked=True)`**(= `FOR UPDATE SKIP LOCKED`).
- **무마이그레이션**: `running`/`locked_at`/실패카운트 컬럼은 추가하지 않음. 동시 패스가 같은 row를 중복 처리하지
  않도록 SKIP LOCKED로 분리.

### tick 실행

- 선택된 계획마다 **M2.14B-2 `tick_plan_once` 코어를 재사용**(신호 생성 로직 중복 0 — 디스패처가 직접
  `SignalLog()`/`evaluate_session`/SignalService를 호출하지 않음). D-26 의미론 유지: completed_runs=시도 횟수,
  max_runs→`completed`+next_run_at null, 선택 페어만 ≤2 SignalLog, 제3 세션 무영향, Trade/Order 0.

### 결과 객체

`dispatcher_stage="service_core_direct_invocation_only"` · `scheduler_job_registered=false` ·
`api_execution_endpoint_registered=false` · `config_enabled` · `can_execute` · `requested/effective_batch_limit` ·
`selected/processed/completed/failed/skipped_plan_ids` · `blocked_reason` · `plans_selected/plans_processed` ·
`signals_created` · `orders_created=0` · `trades_created=0` · `warnings`.

### readiness API 갱신

`dispatcher_stage="service_core_direct_invocation_only"` + `service_core_implemented=true` ·
`scheduler_dispatcher_implemented=false` · `api_execution_endpoint_registered=false` · `can_execute=false`
(외부/스케줄 실행은 여전히 불가) · 읽기 전용 유지(디스패처 미실행).

### 아직 미구현(다음 단계, 별도 명시 승인)

- **스케줄러 통합**(3d, 신규 잡 + 플래그 뒤 · 기본 false). 잡 함수 첫 줄에서 디스패처 플래그 검사 →
  `run_now` 우회돼도 no-op.
- **API 실행 라우트**(없음 — readiness 외 디스패처 실행 엔드포인트 미추가).
- **프론트 컨트롤**(3e, 읽기전용 status만).
- **프로덕션 디스패처 활성**(플래그는 기본 false 유지).

### 동시성 한계 메모

- 단일 디스패처 인스턴스 가정. SKIP LOCKED는 선택 시점 분리를 보장하나, `tick_plan_once`가 계획마다 커밋하므로
  첫 커밋 후 그 트랜잭션의 잔여 락이 해제된다. 각 tick이 next_run_at을 미래로 밀어 곧바로 재-due되지 않으므로
  순차 호출 중복 tick은 발생하지 않는다(테스트로 보장). 다중 워커/강한 in-flight 가시성이 필요하면 3d에서
  `running`/`locked_at` 컬럼(별도 마이그레이션·승인)을 검토한다.

## 17. M2.14B-3e — Read-only frontend dispatcher status (구현됨, 컨트롤 아님)

M2.14B-3e는 기존 readiness API를 프론트에 **읽기 전용 상태**로 노출한다. **이 UI는 컨트롤 표면이 아니라 상태
표면이다** — 실행/활성화/스케줄러/설정 토글 버튼이 없고, mutation도 없다(GET readiness만).

- 컴포넌트: `RecurringDispatcherStatusPanel`(`StrategyProposalReportCard` > `ChallengerComparison` 내
  `<details> "디스패처 상태(읽기 전용)"`). API 바인딩 `getPaperSignalRecurringDispatcherReadiness()`(GET).
- 표시: 안전 배지 8종 + 상태 카드 7종(실행 가능 여부/서비스 코어/스케줄러/설정 플래그(토글 없음)/계획 카운트/
  안전 불변식/warnings). "due 계획이 있어도 현재는 자동 실행되지 않습니다" 명시.
- 무실행/무변경: POST/PATCH/DELETE 0 · dispatch/scheduler/config-toggle 호출 0 · `useEffect`/`setInterval`/
  `setTimeout`/폴링 없음(수동 "상태 새로고침" 버튼만). 백엔드/마이그레이션 변경 없음.
- **스케줄러 통합(3d)은 여전히 별도·미승인·미착수.** 이 단계는 무인 실행 표면을 0으로 유지한 채 가시성만 제공.
