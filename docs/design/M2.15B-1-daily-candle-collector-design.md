# M2.15B-1 — Daily Candle Collector Design (Leader Trend Following)

> 설계/문서 전용. 수집기 구현 없음 · 백엔드/프론트 런타임 변경 없음 · 마이그레이션 없음 · 라이브 KIS 호출 없음 ·
> broker/KIS 주문 없음 · SignalLog/Trade/Order 없음 · 스케줄러/디스패처 없음 · 실거래 없음 · M2.14B-3d 승인 아님.
> 목적: M2.15B(NOT_READY) 이후, 52주 분석을 위한 **일봉 수집**을 안전·rate-limit 인지로 설계.

## 1. Executive summary

- 현 dev DB는 **일봉 0**(market_data 269,636행 전부 1m/5m 인트라데이, ~10 거래일). 52주 분석 불가(M2.15B).
- **저장은 무마이그레이션 가능**: 기존 `market_data`에 `timeframe="1d"`로 적재(PK `(symbol, timeframe, ts)`로
  멱등 upsert). **인트라데이 행과 혼동 없음**(timeframe로 구분).
- **수집은 신규 KIS read-only 일봉 메서드 + rate-limit 인지 배치 + 캐시-first**가 필요(M2.14O 하드닝 패턴 재사용).
- `trading_value`는 V1 **불필요**(volume + close×volume 근사) → 컬럼 추가는 나중 별도 승인 마이그레이션.
- 이 문서는 설계만. 구현은 M2.15B-2(KIS 메서드+서비스+스크립트, **별도 승인**)부터.

## 3. Storage design

**기존 `market_data` 재사용(무마이그레이션).**

- `symbol_code` · `timeframe="1d"` · `ts`=**시장일(거래일)** 표현(예 거래일 KST 00:00, fetch 시각 아님) ·
  `open/high/low/close`(Numeric) · `volume`(BigInteger). PK `(symbol_code, "1d", ts)`.
- **멱등 upsert**: 같은 (symbol, "1d", ts) 재수집 시 갱신만(중복 행 없음). **인트라데이(1m/5m) 행은 절대
  덮어쓰지/혼동하지 않음**(timeframe 분리).
- 모델 한계(현 스키마): **`trading_value`/`source`/`adjusted`/`created_at`/`updated_at` 컬럼 없음.** →
  V1은 OHLCV+volume만 저장. source/adjusted 메타가 필요해지면 **별도 승인 마이그레이션**(지금 안 만듦).
- `ts` 정규화 규칙(중복 방지 핵심): 거래일을 단일 canonical timestamp로(예 KST 자정). 일·주·월 혼선 방지 위해
  일봉은 `timeframe="1d"`만 사용.

> 결론: 일봉 저장은 **신규 마이그레이션 불필요**. 메타(거래대금/수정주가 플래그)가 필요하면 그때 별도 승인.

## 4. trading_value decision

| 옵션 | 내용 | 평가 |
|------|------|------|
| **A(권장)** | **첫 수집기는 OHLCV만** · 유동성은 volume(+close×volume 근사)로 시작 · trading_value 나중 | **보수적·무마이그레이션** |
| B | `trading_value ≈ close*volume` 파생 | 근사값임을 명시(거래소 제공값 아님) — A의 일부로 흡수 |
| C | 컬럼 추가 마이그레이션 | V1 불필요 — 정밀 거래대금이 정말 필요할 때 **별도 승인** |

**권장: A.** V1 유동성 필터는 volume 하한 + (표시용) close×volume 근사. `trading_value` 컬럼/마이그레이션은
보류(별도 승인). **지금 마이그레이션 만들지 않음.**

## 5. KIS read-only daily candle API design (미구현 — 미래 메서드 계약)

기존 분봉은 `/uapi/domestic-stock/v1/quotations/inquire-time-itemchartprice`(TR `INQUIRE_TIME_ITEMCHARTPRICE`).
일봉은 **`inquire-daily-itemchartprice`(일/주/월 차트, TR `FHKST03010100`로 추정)** — **정확한 경로/TR ID·필드명은
구현 시점 KIS 문서로 확정해야 하는 미확인 항목**(여기서 단정하지 않음).

제안 메서드(이름은 기존 컨벤션 따름):
```
async def get_daily_candles(symbol, start_date=None, end_date=None, count=252, adjusted=False)
    -> list[DailyCandle]
```
- **요청 파라미터(예상)**: 종목코드 · 기간(start/end) 또는 조회구간 · 일봉 구분(D) · 수정주가 여부 플래그 ·
  시장분류(필요 시 KOSPI/KOSDAQ).
- **응답 필드(예상)**: 일자 · open/high/low/close · volume · (가용 시)거래대금 · 수정주가 여부.
- **출력 DTO**: 신규 `DailyCandle`(date, open, high, low, close, volume[, trading_value]) — read-only.
- **에러/빈데이터/rate-limit**: M2.14O 패턴 — transient(5xx/429/timeout) 분류 + bounded 재시도 + 마스킹 +
  degraded(부분 성공) · 빈 응답/결측("." 등) 안전 skip · **가짜 데이터 미생성**.
- **페이지네이션**: KIS 일봉은 1회 ~100건 한도 가능성 → 252봉엔 **기간 분할/페이지** 필요(구현 시 확정).
- **수정주가/거래량/거래대금 가용성**: 엔드포인트 옵션 의존 — **구현 시 확인할 research item**.
- **주문 무관**: 시세 read-only만. 주문 TR/`broker.place_order` 절대 미사용.

## 7. Rate-limit / retry / cache design (M2.14O 원칙 재사용)

- **동시성 1**(처음) · 요청 간 간격/backoff · transient(5xx/429/timeout/네트워크)만 bounded 재시도(예 최대 3) ·
  **무한 재시도 없음**.
- provider 장애가 **DB 손상으로 이어지지 않음**(부분 성공 보고, 좋은 캐시 보존, 가짜 데이터 미기록).
- **per-symbol status**: `success` · `skipped_fresh`(이미 최신 일봉 보유) · `failed_transient` · `failed_permanent`
  · `insufficient_data`.
- **마스킹 로깅**: api_key/token·전체 raw URL(시크릿 포함) 미노출(M2.14O `redact_api_key`).
- **resume**: 종목별 최신 보유 일봉 이후만 증분 수집(멱등). stale 캐시는 보존.

## 8. Collector operation modes

1. **Dry-run**(기본): DB 쓰기 0 · 계획 종목/기간/예상 요청수/rate-limit 위험 출력.
2. **Execute pilot**: 명시 확인 필요 · **일봉 market_data만** 멱등 upsert · SignalLog/Trade/Order 0.
3. **Coverage report**(읽기 전용): 종목별 일봉 수 · 20/50/120/252 충족 · M2.15C readiness 표시.
4. **Repair/backfill**(미래·별도 승인): 한정 기간만.

**이 단계 스케줄러 모드 없음 · autonomous 잡 등록 없음.**
