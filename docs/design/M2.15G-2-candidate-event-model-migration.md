# M2.15G-2 — Leader Trend CandidateEvent Model + Migration

> **schema + model only.** 저장 service/API/repository 0 · record 생성 0 · seed 0 · production migration 실행 0 ·
> DB runtime write 0 · 외부/KIS 0 · SignalLog/Trade/Order 0 · 스케줄러 0 · frontend 0.
> **CandidateEvent record는 매수 신호가 아니다.**

## 1. Naming decision (중요)

기존에 이미 **`candidate_events` 테이블 / `CandidateEvent` 모델**이 존재한다(C-2.24 스캐너 룰 후보,
`scanner_rule_versions` FK). M2.15G-1 설계가 제안한 이름과 **충돌**하므로, 운영 데이터/기존 파이프라인에 영향을
주지 않기 위해 **별도 이름**으로 추가했다:

- model: **`LeaderTrendCandidateEvent`**
- table: **`leader_trend_candidate_events`**

(설계 의도는 동일 — leader trend research candidate 관찰 기록. force-fit 금지 규칙에 따라 신규 테이블로 분리.)

## 2. Table fields

`id` · `symbol` · `detected_at`(tz) · `reference_date`(date) · `timeframe` · `universe_scope` · `scanner_name` ·
`scanner_version` · `candidate_bucket` · `is_operational_candidate`(bool, default false) · `strategy_extreme`(bool,
default false) · `current_price`/`low_52w`/`high_52w`(Numeric(18,4), not null) · `low_52w_gain_pct`/
`drawdown_from_52w_high_pct`(Numeric(14,4), nullable) · `window_basis` · `data_source`(default local_market_data) ·
`validation_source`(nullable) · `validation_status` · `validation_report_path`(nullable) ·
`research_only`(bool, default true) · `not_buy_signal`(bool, default true) · `created_at`(tz, default now) ·
선택: `notes` · `source_basis_note` · `provenance_warning` · `safety_warning`.

타입: 가격/비율은 기존 market/strategy 컨벤션의 **Numeric**. enum 대신 **String + CheckConstraint**(migration/
downgrade 단순화).

## 3. Constraints

- **Unique**: `(symbol, scanner_name, scanner_version, reference_date, timeframe, window_basis, universe_scope)`
  → `uq_ltce_symbol_scanner_reference_window_scope` (중복 후보 저장 방지).
- **Check**:
  - `candidate_bucket in ('A','B','none')`
  - `window_basis in ('last_252_trading_rows','calendar_52_weeks','source_reported')`
  - `validation_status in ('matched','minor_diff','explained_major_diff','unresolved_major_diff','not_validated')`
  - `research_only = true` (DB 강제)
  - `not_buy_signal = true` (DB 강제)

## 4. Indexes

`(reference_date, scanner_name)` · `(symbol, reference_date)` · `(candidate_bucket, reference_date)` ·
`(validation_status, reference_date)`.

## 5. Forbidden relationships (FK 없음)

Order · Trade · SignalLog · broker/KIS · StrategyRunner · StrategyVersion · Account · Portfolio — **어떤 FK도 없다.**
`__table__.foreign_keys`는 비어 있다(테스트로 보장).

### Why no FK to trading tables

후보 이벤트는 **research observation record**이지 strategy execution record가 아니다. 거래/주문/신호 테이블과
FK로 묶이면 "후보=거래 트리거"로 오해될 수 있고 안전 모델을 깨뜨린다. 연구 데이터셋은 거래 경로와 **물리적으로
분리**한다.

## 6. Why no records are created yet

G-2는 **model + migration only**. record 생성에는 service/repository/explicit create API + validation policy
(unresolved_major_diff reject, explained_major_diff는 source_basis_note 필수)가 선행돼야 하며, 이는 M2.15G-3/G-4의
별도 승인 단계다. **production migration도 실행하지 않는다**(테스트 DB에서만 upgrade 검증).

## 7. Migration

- revision `r1s2t3u4v5w6`, down_revision `q1r2s3t4u5v6`(현 head 위 additive).
- upgrade: `leader_trend_candidate_events` create_table + 4 index. downgrade: index drop + table drop(가역).
- **data migration/seed/INSERT/UPDATE/DELETE 없음**, 기존 테이블 수정/FK 추가 없음(테스트로 보장).
- 적용 범위: **테스트 DB만**(conftest `alembic upgrade head`). dev/production DB 미적용 — code head는
  r1s2t3u4v5w6이나 dev DB current는 q1r2s3t4u5v6 유지.
