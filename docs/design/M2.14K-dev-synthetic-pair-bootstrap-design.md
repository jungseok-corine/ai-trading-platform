# M2.14K — Dev-only Synthetic Pair Bootstrap (Design)

> 설계/문서 전용. **스크립트 미구현 · DB에 데이터 미생성 · 런타임/마이그레이션 변경 없음 · 가짜 SignalLog/
> Trade/Order 없음 · broker/KIS 없음 · 스케줄러/디스패처 활성 없음 · M2.14B-3d 승인 아님.**
> 목적: 빈 dev DB에서 **수동 tick UI 흐름을 시연**할 수 있도록 최소 baseline/challenger/계획 레코드를 만드는
> **dev 전용 SYNTHETIC** 부트스트랩의 계약을 설계한다(실 거래 증거로 위장하지 않는다).
>
> 관련: [선행 체크리스트(M2.14J)](../runbooks/M2.14J-data-collection-prerequisite-checklist.md) ·
> [수동 수집 퀵스타트(M2.14H)](../runbooks/M2.14H-manual-data-collection-quickstart.md).

## 1. Current state

- dev DB 비어 있음(M2.14J): sessions=0 · signal_challenger=0 · recurring_plans=0.
- 빈 DB에서 운영자가 baseline/challenger 페어를 만드는 경로 부재(상류 스캐너/제안 파이프라인 또는 테스트
  fixture 의존). 3 플래그 false · 디스패처 미연결 · M2.14B-3d 미승인.

## 2. 검증이 요구하는 최소 레코드(코드로 확인)

`PaperSignalSessionRunOnceService.validate_session` + 페어 관계(M2.10) 기준:

- session.status == `active` · session.strategy_version_id 존재 · 버전.status == `DRAFT` ·
  `parameters.auto_trade_enabled` falsy · session.symbol_code 존재 · `parameters.strategy_type`가 **등록된**
  타입(예 `moving_average_cross`) · `create_strategy(strategy_type, params)` 성공.
- 페어: challenger.source_type == `signal_challenger` · challenger.baseline_session_id == baseline.id ·
  baseline.symbol_code == challenger.symbol_code.

### 2a. 엄격히 필요(strictly required)

1. **Strategy** ×1(StrategyVersion 부모).
2. **StrategyVersion** ×2 — `status=DRAFT`, `parameters={strategy_type:"moving_average_cross",
   symbol_code:<symbol>, auto_trade_enabled:false}`.
3. **PaperSignalSession baseline** — `status=active`, `source_type="candidate_proposal"`(challenger 아님),
   `symbol_code`, `strategy_version_id`=baseline 버전, `started_by`.
4. **PaperSignalSession challenger** — `status=active`, `source_type="signal_challenger"`,
   `baseline_session_id`=baseline.id, `symbol_code`(동일), `strategy_version_id`=challenger 버전, `started_by`.
5. **PaperSignalRecurringRun** — **서비스 `create_prepared_pair_plan`로** 생성(prepared). 직접 insert 대신
   검증 경유 권장(드리프트 방지).

### 2b. FK 충족/표시용(선택 — 전부 nullable)

ScannerRule/ScannerRuleVersion · CandidateEvent · CandidateStrategyProposal · StrategyProposal.
세션 FK(candidate_strategy_proposal_id / source_strategy_proposal_id / candidate_event_id / experiment_id)는
**전부 nullable**이라 **검증엔 불필요**. 단 **제안 카드 UI 진입/표시**가 제안 컨텍스트를 요구하면 그때만
최소 StrategyProposal/CandidateStrategyProposal를 추가(표시용).

### 2c. 절대 만들지 않음

SignalLog · Trade · Order · 스케줄러 잡 · 디스패처 활성 · 실계좌/주문. (tick은 부트스트랩이 수행하지 않음.)

## 3. Bootstrap contract (미래 스크립트)

제안 경로: `backend/scripts/dev_seed_synthetic_signal_pair.py`.

**Inputs**: `--symbol`(기본 "005930") · `--interval-seconds`(60) · `--max-runs`(30) · `--confirm`(필수) ·
환경 플래그(예 `APP_ENV=development|test`) · `--dry-run`(기본 true) · `--force-new`(기본 false) ·
선택 `--cleanup`(라벨된 SYNTHETIC만).

**동작(dry-run=false·confirm 시)**: §2a 레코드 생성 + (선택)§2b 표시용 최소 + 계획 **prepared**까지만.
**activate/tick 안 함**(운영자가 UI/H로 수동 수행).

**Output**: strategy id · baseline/challenger 버전 id · baseline/challenger 세션 id · 반복 계획 id ·
`SYNTHETIC/DEMO` 라벨 · "성과 증거 아님" 경고 · 다음 안전 행동(데모임을 수용하면 M2.14H로 수동 tick).

## 4. Hard guards(모두 통과해야 실행)

- `APP_ENV`가 production 계열이면 **거부**(기본 development/test만 허용).
- `--confirm` 없으면 **거부** · 기본 `--dry-run`(미지정 시 아무것도 안 만듦).
- `KIS_REAL_TRADING_ENABLED=true` / `paper_signal_session_runner_enabled=true` /
  `paper_signal_recurring_plan_dispatcher_enabled=true` 중 하나라도 true면 **거부**.
- 디스패처/런너 스케줄러 잡이 등록·활성이면(감지 가능 시) **거부**.
- `database_url`이 local/dev/test로 안 보이면(가능 시 host/db명 검사) **거부**.
- **절대**: broker/KIS 호출 · Trade/Order 생성 · SignalLog 생성 · tick 실행 · 스케줄러/디스패처 활성 ·
  M2.14B-3d 승인 · 실데이터 삭제.

## 5. Data labeling(모든 합성 레코드)

- 라벨 토큰: `SYNTHETIC` · `DEMO` · `NOT_TRADING_EVIDENCE` · `NOT_REAL_PERFORMANCE` · `DEV_ONLY`.
- 위치: Strategy `name`/`description` · 세션 `note`(Text) · 계획 `note` · StrategyVersion params에
  `_synthetic:true`(있으면) · `started_by="dev_synthetic_bootstrap"`.
- 명시: 이 데이터의 어떤 비교도 **UI/흐름 검증용일 뿐** — 전략 수익성 판단/3d 정당화/실 거래 증거로 **사용 금지**.

## 6. Idempotency

- 고유 라벨/note/symbol로 기존 SYNTHETIC 페어를 **찾아 재사용**(중복 무분별 생성 금지).
- 새로 강제하려면 `--force-new`.
- 실데이터(라벨 없는 레코드) **덮어쓰기/삭제 금지**.

## 7. Cleanup

- 기본: **수동 정리 쿼리/체크리스트 문서화**(SYNTHETIC 라벨 레코드만 SELECT로 식별 후 사람이 판단).
- 선택: 미래 안전 `--cleanup` 모드 — **라벨된 SYNTHETIC/DEMO만** 대상, 라벨 없는 실데이터 절대 미접근.
- **reset/purge 스크립트 없음**(CLAUDE.md 금지). 파괴적 일괄 삭제 금지.

## 8. Validation expectations(부트스트랩 후)

M2.14J 선행조건을 "실 증거" 항목만 빼고 통과해야 함:
- 유효 baseline/challenger 페어 1개 · challenger=signal_challenger · 둘 다 active·같은 종목 · 두 버전 DRAFT ·
  auto_trade off · 반복 계획 1개(기본 prepared) · **부트스트랩이 SignalLog/Trade/Order 0** · broker 미호출 ·
  3 플래그 false 유지.

## 9. Risks & mitigations

| 리스크 | 완화 |
|--------|------|
| 합성을 실 성과로 오인 | 강한 라벨 5종 · "NOT_TRADING_EVIDENCE" · 비교 결과에 데모 표식 권장 |
| 테스트 fixture 로직 무분별 복사 | `_make_pair`는 **참고만**, 도메인 제약 충족 여부 직접 검증(서비스 경유 권장) |
| 프로덕션 레코드 실수 생성 | APP_ENV/DB URL 가드 · confirm · 기본 dry-run |
| 데모 클러터/중복 | 라벨 idempotency · `--force-new` 필요 |
| cleanup이 실데이터 삭제 | 라벨된 SYNTHETIC만 · reset/purge 금지 · 기본 수동 정리 |
| 시세 의존 잔존 | 부트스트랩은 페어만; 유용 SignalLog엔 (모의)시세 필요(H에서) |
| UI가 라벨 없이 합성 표시 | note/name에 SYNTHETIC 노출 · 데모 운영자 인지 |
| 실 표본 전 3d 압박 | 본 설계는 데모 언블록일 뿐 — 3d 미승인 명시 |

## 10. Recommendation

**구현할 가치 있음 — 단 dev/demo 언블록 한정.**
- 작고 강하게 가드된 스크립트로 구현(별도 작업 M2.14L(가칭), 명시 승인 후).
- 구현 뒤엔 **데모로 명확히 라벨된 M2.14H 시연 1회**가 따른다(실 증거 아님).
- **실 수동 데이터 수집은 여전히 실 상류 데이터 + (모의)시세 접근 필요.**
- **M2.14B-3d는 계속 blocked.** 합성 데이터는 자동화를 정당화하지 못한다.

## 11. Non-goals

스크립트 구현(이 작업) · 데이터 생성 · seed 실행 · 실거래 · broker 주문 · Trade/Order · SignalLog 생성 ·
스케줄러/디스패처 활성 · 프로덕션 영향 · 3d 승인 · reset/purge.
