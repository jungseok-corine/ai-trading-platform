# M2.15A — Leader Trend Following Strategy (주도주 추세추종) Design

> 설계/문서 전용. 백엔드/프론트 런타임 구현 없음 · 마이그레이션 없음 · SignalLog/Trade/Order 없음 ·
> broker/KIS 주문 없음 · 스케줄러/디스패처 활성 없음 · 실거래 없음 · M2.14B-3d 승인 아님.
> 본 전략군은 **paper 연구 우선**이며, 궁극적으로 **paper SignalLog만** 생성한다(주문/거래 절대 없음).

---

## 1. Current architecture fit (코드 확인)

- **Strategy 인터페이스**(`app/trading/strategy/base.py`): `generate_signal(symbol_code, candles, version_id,
  context) -> Signal | None`. 8개 전략이 `registry._REGISTRY`에 등록(MA-cross/breakout_high/pullback_trend/
  momentum_surge 등). **새 전략 = 클래스 1개 + 레지스트리 등록**이면 runner 수정 없이 동작.
- **SignalLog 경로**: 전략 Signal → M2.8 `evaluate_session`(`SignalService.generate_and_log_signal`) →
  **SignalLog만**. 주문/거래 미구성(이 프로젝트의 핵심 불변식).
- **Scanner**(`app/trading/scanner/`): `facts.py`(volume_ratio/price_change_pct/turnover_rank/flow) +
  `conditions.py` + `macro_score.py` → ScannerRule/Version → CandidateEvent → CandidateStrategyProposal.
  **52주 고저(high/low) fact는 아직 없음**(신규 fact 필요).
- **시세 저장**(`MarketData(symbol_code, timeframe, ts)` + OHLCV): timeframe별 캔들 저장 가능. 단 현재 SignalLog
  runner 경로는 **분봉(MinuteCandle)** 위주 — **52주 분석엔 일봉 ~252개**가 필요(데이터 갭, §5).
- **테마/섹터**: `Theme` + `SymbolThemeMembership`(C-2.22) 존재 → 테마 클러스터링 데이터 부분 가용(V2).

### 아키텍처 배치 결론

주도주 추세추종은 **두 부분으로 분리**해 기존 자산을 재사용한다(둘 다 SignalLog-only):

1. **주도주 스캐너** = 신규 scanner facts/condition(52주 지표 계산) → CandidateEvent →
   CandidateStrategyProposal. (전용 read-only 스캐너 서비스로 시작 가능.)
2. **추세추종 신호** = 신규 `Strategy` 서브클래스 `leader_trend_following`(레지스트리 등록), `generate_signal`로
   Signal 생성 → 기존 paper 경로로 **SignalLog만**. 주문 instruction 없음.

→ "scanner rule + strategy version" **조합**. 후보 발견(스캐너)과 진입/청산 신호(전략 버전 파라미터)를 분리한다.

## 2. Strategy interpretation (사용자 개념 정식화)

- `low_52w_gain_pct = (current_price / low_52w - 1) * 100`
- `drawdown_from_52w_high_pct = (high_52w - current_price) / high_52w * 100`
- **Condition A**: `low_52w_gain_pct <= 200` AND `drawdown_from_52w_high_pct <= 10`
- **Condition B**: `low_52w_gain_pct >= 200` AND `drawdown_from_52w_high_pct <= 20`

**이는 후보 필터일 뿐 매수 신호가 아니다.** 별도 추세추종 진입/청산 시스템이 후보 위에서 동작한다.
공통 테마/섹터/업종군 종목을 선호(가점)하되 V1에서는 가용 데이터 한도 내에서만.

## 3. V1 leader scanner design (후보 스캐너)

**입력**: symbol universe · 일봉 ~252개(현재 종가/52주 high/52주 low) · 거래량 · 거래대금(가용 시) ·
벤치마크/지수(가용 시).

**지표(read-only 계산)**: low_52w_gain_pct · drawdown_from_52w_high_pct · volume_expansion_ratio(현재/20일 평균) ·
average_trading_value · recent_high_breakout(최근 20일 신고가 여부) · trend_score(MA 정렬/기울기 합성) ·
relative_strength_score(벤치마크 대비, 가용 시) · market_regime_score(선택).

**후보 클래스**: `LeaderCandidateA`(A 조건) / `LeaderCandidateB`(B 조건).

**추가 필터**: 최소 유동성(평균 거래량/거래대금 하한) · 정지/저유동 제외(데이터 있으면) · 1일 비정상 급등 회피 ·
이미 추세 이탈한 종목 제외 · 시장 레짐 필터(선택) · 테마 클러스터 점수(데이터 있으면 가점).

**reason codes**: `NEAR_52W_HIGH` · `STRONG_FROM_52W_LOW` · `VOLUME_EXPANSION` · `LIQUIDITY_OK` ·
`RELATIVE_STRENGTH_OK` · `THEME_CLUSTER_UNKNOWN_OR_MISSING` · `REJECT_ILLIQUID` ·
`REJECT_TOO_FAR_FROM_HIGH` · `REJECT_ABNORMAL_SPIKE` · `REJECT_INSUFFICIENT_CANDLES`.

## 4. V1 trend-following signal design (후보와 분리)

**BUY 후보**: (A 또는 B) AND close>MA20 AND close>MA50 AND MA20>MA50 AND 최근 20일 신고가 돌파 AND
거래량>20일 평균×임계 AND (선택) 시장 레짐 risk-off 아님.

**대안 눌림목 진입**: (A 또는 B) AND price>MA50 유지 AND MA20/직전 돌파선 부근 눌림 AND close가 MA20 회복 AND
거래량 확인.

**HOLD**: 추세 유효 · close>MA20(또는 트레일링 스탑 위) · 청산 룰 미발동.

**EXIT**: close<MA20 OR close<최근 10일 저가 OR 최근 고점 대비 낙폭 임계 초과 OR ATR 트레일링 스탑(ATR 가용 시) OR
시장 레짐 risk-off OR 최대 보유일 초과(필요 시).

**출력 enum**: `BUY` · `HOLD` · `EXIT` · `NO_SIGNAL` · `SKIP`. 각 출력에 signal type · confidence/score(선택) ·
reason codes · skip reasons · metrics snapshot 포함. **주문 instruction 없음.**

> 출력은 연구 전용이며 궁극적으로 **paper SignalLog만** 만든다 — Trade/Order/broker 절대 없음.

## 6. Data requirements & gaps

**지금 가용**: `MarketData` OHLCV(timeframe별) · `Theme`/`SymbolThemeMembership`(부분 테마) · scanner
facts(volume/price/flow) · InvestorFlow(수급) · StrategyVersion params 구조 · paper SignalLog 경로.

**V1 필요**: 종목별 **일봉 ~252개**(현재 종가/52주 high·low) · 거래량 · 평균 거래량 · 거래대금(가용 시) ·
symbol universe. **갭**: 52주 high/low **fact 미존재**(신규 계산 필요), 일봉이 **대규모로 수집·저장돼 있는지 불확실**
(현 SignalLog 경로는 분봉 중심) → **M2.15B 데이터 준비 진단 필요**.

**V2 필요**: 섹터/업종 분류 · 테마 그룹 · peer 상대강도 · 벤치마크 상대강도 · 시장 레짐 데이터.

**V3 필요**: 뉴스/테마 AI 분류 · 촉매(catalyst) 탐지 · 외국인/기관 수급(가용 시) · 실적/이벤트 데이터.

**KIS/오픈API·rate-limit·캐시 관점**: 일봉 대량 수집은 KIS API 호출량이 크다 → **rate-limit 리스크**(M2.14O FRED
교훈처럼 backoff/degraded 필요). 캐시 `market_data` 테이블이 일봉을 보유하면 충분; 없으면 **스캐너 구현 전 배치
수집 단계가 선행**돼야 함(M2.15B/C에서 판단). **신규 마이그레이션은 V1에서 불필요**(MarketData/ScannerRule/
StrategyVersion/Theme 재사용); 후보 영속 전용 테이블이 필요해지면 그때 별도 승인 마이그레이션.

## 8. Fit with the existing M2.14 research loop

- 스캐너가 후보 발견 → StrategyVersion이 `leader_trend_following` 파라미터 저장 → paper 세션으로 baseline↔
  challenger 비교 → 선택 세션을 **수동 recurring-plan tick**으로 평가 → **SignalLog-only** → 비교/성과 리뷰.
- **자동매매 없음 · 스케줄러/디스패처 확장 없음**(M2.14B-3d 미승인 유지). 무인 실행은 충분한 실 표본 + 별도 승인 후.

### 기존 것과의 차이

- **MA-cross 전략과 차이**: MA-cross는 단순 교차. 주도주 추세추종은 **52주 상대 위치(주도주 필터) + 추세 정렬 +
  신고가 돌파 + 거래량 확인 + (선택)상대강도/테마**를 결합 — *후보 선별*과 *추세 진입*을 분리.
- **SYNTHETIC/DEMO 페어와 차이**: 데모 페어는 흐름 검증용 가짜 라벨 데이터(거래 증거 아님). 주도주 전략은 **실
  시세 일봉** 기반 연구 신호.
- **미래 실 paper 수집과 차이**: 본 설계는 *어떤 신호를 만들지*를 정의; 실 수집은 실 일봉 데이터 + (모의)시세 +
  운영자 수동 tick이 갖춰져야 시작(M2.15B 이후).

## 9. Safety constraints

실거래 없음 · Trade 없음 · Order 없음 · broker/KIS 주문 API 없음 · `auto_trade_enabled=true` 없음 ·
스케줄러 통합 없음 · 디스패처 통합 없음 · M2.14B-3d 승인 없음 · **paper SignalLog-only**. 전략 출력은 **연구
후보**이지 추천이 아니며, 백테스트/paper 결과는 미래 성과를 보장하지 않는다.

## 10. Decision note

새 durable decision은 추가하지 않는다 — 본 문서는 설계일 뿐 아키텍처 결정(전역 정책 변경)이 아니며, 기존
불변식(SignalLog-only, 자동매매 금지, 스케줄러 미확장)을 그대로 따른다. M2.15D에서 **후보 영속 전용 테이블 +
마이그레이션**이 필요하다고 판단되면 그 시점에 D-28(가칭)로 기록 + 별도 승인.
