### 1-5. 캐시/스토리지 구조

DartLab은 **DuckDB + HuggingFace Parquet**를 데이터 저장소로 사용한다:

```
첫 실행 시:
  HuggingFace eddmpython/dartlab-data
      → 로컬 data/dart/finance/{code}.parquet
      → DuckDB 캐시

이후:
  로컬 Parquet → DuckDB LRU 캐시 (메모리)
```

우리 시스템과의 충돌:
- **DB 충돌**: DartLab은 DuckDB(임베디드), 우리는 PostgreSQL(공유 서버). 데이터가 분리됨.
- **네트워크 의존**: 컨테이너 환경에서 HuggingFace 접근이 막히면 초기화 실패.
- **파일시스템 캐시**: DartLab이 `data/` 디렉토리에 Parquet 파일을 직접 생성. 서버 환경에서 디스크 관리 필요.

## 3. DartLab 핵심 API 분석

import dartlab

# 종목 재무제표 (이것이 우리에게 없는 핵심 가치)

## 4. 결론

### 최종 판정: **부분 사용 (Partial Use)**

DartLab을 메인 백엔드 의존성으로 추가하는 것은 **비권장**. 이유:

1. **무게**: 22.5 MB + 의존성 200~500 MB → 서버 앱에 부적합
2. **아키텍처 충돌**: DuckDB + HuggingFace 패턴이 PostgreSQL + httpx 패턴과 근본적으로 다름
3. **설계 목적 불일치**: DartLab은 분석가/연구자용 노트북 도구. 우리는 백엔드 API 서비스.
4. **async 미지원**: 동기 API라 FastAPI와 통합 시 스레드 격리 필요

### 유일한 가치: 재무제표(XBRL) 데이터

우리에게 없는 것이 딱 하나 있다:  
**DART XBRL 재무제표** — 손익계산서, 재무상태표, 현금흐름표, 재무비율

이것은 AI 분석 bundle의 질을 크게 높일 수 있다.  
단, 이를 위해 DartLab 전체를 추가할 필요는 없다.

## 5. 권장 아키텍처: 직접 구현 (대안)

DART API가 재무제표 조회를 직접 제공한다 (`fnlttSinglAcnt.json`).  
DartLab 없이 기존 패턴(`DartProvider` 스타일)으로 직접 구현할 수 있다.

```python
# 구현 예시 스케치 (C-2.21.1에서 실제 구현)
class DartFinanceProvider:
    """DART XBRL 재무제표 수집 — DartProvider 동형 패턴."""

    DART_FINSTATE_URL = "https://opendart.fss.or.kr/api/fnlttSinglAcnt.json"

    def __init__(self, api_key: str | None, *, client: httpx.AsyncClient | None = None):
        self._api_key = api_key
        self._client = client

    async def fetch_statements(
        self,
        corp_code: str,   # DART 고유번호 (8자리)
        bsns_year: str,   # 사업연도 (YYYY)
        reprt_code: str = "11011",  # 11011=사업보고서, 11012=반기, 11013=Q1, 11014=Q3
        fs_div: str = "OFS",  # OFS=개별, CFS=연결
    ) -> list[FinancialStatement]:
        """단일 재무제표 조회 — 비동기, httpx 기반, MockTransport 테스트 가능."""
        ...
```

DART 재무제표 API 추가 시 필요한 것:
- `DartFinanceProvider` 클래스 (httpx 기반, async)
- `DartFinanceIngestService` (corp_code → PostgreSQL 저장)
- `FinancialStatement` 도메인 모델 (DB)
- AI 분석 bundle에 재무 요약 주입
- 테스트 (MockTransport)

**의존성 추가 없음.** 이미 있는 `httpx`, `SQLAlchemy`, `alembic`만 사용.

## 6. DartLab을 사용하는 유일한 정당한 케이스

DartLab이 의미 있는 경우는 하나뿐이다:

> **오프라인 사전 처리(Offline ETL)**: DartLab을 백엔드와 분리된 스크립트/Jupyter에서 실행해  
> 전처리된 재무 데이터를 PostgreSQL에 bulk insert하는 방식.

```
[DartLab CLI / Script] → 재무제표 수집 + 정규화
    → PostgreSQL (bulk INSERT via psycopg/asyncpg)
    → 우리 백엔드 API가 DB에서 읽음 (DartLab 의존 없음)
```

이 경우 메인 FastAPI 앱에 DartLab을 추가할 필요가 없다.  
`backend/scripts/` 아래 별도 스크립트로만 사용 가능.

## 7. 다음 단계 권장사항 (C-2.21.1 입력)

**권장**: DART 재무제표 수집기를 DartLab 없이 직접 구현한다.

C-2.21.1에서 구현할 것:
1. `DartFinanceProvider` — DART `/api/fnlttSinglAcnt.json` async 클라이언트
2. `FinancialStatement` DB 모델 (corp_code, year, quarter, account, amount)
3. `DartFinanceIngestService` — watchlist 종목별 연간 재무제표 수집
4. AI 분석 bundle 확장 — 재무 요약(매출/영업이익/부채비율) 주입

**채택하지 않는 이유**:
- DartLab을 main backend 의존성으로 추가하지 않음
- DartLab을 ETL 스크립트로 사용하는 방안은 C-2.22+ 구현 후 재평가
